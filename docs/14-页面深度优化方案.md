# 智枢·智能体平台 页面深度优化方案

版本 V0.1 · 2026-09-06 · 状态：执行中

> 起因：第二阶段（差距补齐）交付后，使用者评价"页面太简单、内容太少、没有深度，像 demo"。本文档是这批优化的需求与执行记录：先盘点，再按批次改，每批同步文档与测试。
> 三个方向由使用者 2026-09-05 确认：**运营统计与趋势**、**对象详情与关联**、**筛选搜索与批量**；图表库用 `@ant-design/plots`；核心对象（智能体、工作流、知识库、运行记录）独立详情页，其余用右侧抽屉；所有页面都做。

## 1. 结论先行

- 盘点结论：15 个页面全是"标题 + 表格 + 增删改弹窗"；后端 17 个筛选参数前端只用 2 个；`/system/status` 的降级汇总前端零消费；运行记录不显示归属；审计明细不可读；全站零排序、零批量、零详情页、零刷新按钮；没有任何按时间聚合的接口。
- 方案：先做一批**后端基础**（统计接口、排序与时间区间、关联字段、批量与启停写口、快照列），再做一批**前端基础设施**（列表骨架、状态字典、时间工具、图表封装、详情页骨架、关联跳转、批量条、降级横幅），然后按页面分 5 批改造。
- 两条规范修订：`07-前端规范.md` 允许 `api/` 按域拆分（`index.ts` 只做 re-export）、知识库文档"有处理中的才轮询"；`09-演进路线.md` 第 5 节"不再增加页面"增加核心对象详情页的例外。

## 2. 盘点摘要（2026-09-05）

| 类别 | 现状 | 证据 |
|---|---|---|
| 筛选 | 只有运行记录页有类型 / 状态两个 Select | 后端 17 个筛选参数（各表 `q`、`agents.status`、`documents.status`、审计三项、`runs` 四项、`conversations.agent_id`）前端只用 2 个 |
| 排序 / 批量 / 详情 | 全站 0 可排序列、0 行选择、0 批量、0 详情页、0 刷新按钮 | `usePagedList` 不支持排序与错误态；只有 Runs 详情 Modal 与 Agents 版本 Modal |

| 数据未展示 | 运行记录不显示智能体 / 工作流 / 用户；审计 `detail` 是 `JSON.stringify` 单行；模型单价、工具 url、Key 创建人、定时任务 input 与下次触发、文档失败原因都看不到 | 后端接口盘点 |
| 契约漏配 | `GET /conversations/{id}/messages` 不返回 `token_usage`（前端在读）；`run_nodes` 有起止时间列但引擎不写；SSE `done` 的 `run_id` 前端丢弃 | 代码核对 |
| 状态文案 | `published / draft / running / ready / rag_retrieve` 英文裸值上屏 | 只有 Runs 类型列做了中文映射 |

## 3. 后端第 0 批（2026-09-06 完成）

### 3.1 通用约定（写进 `04` 2.3、`06` 第 4 节）

- **排序**：列表接口接 `sort` / `order`（`asc` / `desc`，默认 desc），字段按各接口白名单，不在白名单 400 "不支持的排序字段：x"，方向非法 422；排序永远带 `id` 副键。实现 `core/pagination.apply_sort`。
- **时间区间**：`<列>_from` / `<列>_to`，左闭右开 `[from, to)`，必须带时区（否则 400），`from >= to` 400。实现 `core/pagination.time_range`。
- **批量**：`POST /<资源>/batch`，`{ids: [1～100 个], action}`，`action` 各资源 Literal 白名单（422）；逐条独立执行，响应固定 200 `{succeeded: [...], failed: [{id, detail}]}`，业务失败（404 / 409 / 400）进失败清单，每条失败后回滚再继续。实现 `core/batch.run_batch`。
- **关联名称装配**：一页数据的关联对象各用一次 `IN` 查询装配，禁止逐行查（用例用 SQL 计数锁住）。

### 3.2 数据变更

- `runs` 新增 `model_id`（FK models SET NULL）、`conversation_id`（FK conversations SET NULL）、`cost`（double）；索引 `started_at / agent_id / workflow_id / model_id`；`conversations.agent_id` 索引。迁移 `20260906_100000_e8f9g0_runs_stats_snapshot_and_indexes.py`，回填存量 `model_id` 与 `cost`（按当前单价，历史无法还原）。
- 成本口径改为**收尾时快照**：`finalize_run` 按当时模型单价折算写入 `cost`，之后改单价不追溯；按模型聚合按 `runs.model_id`（智能体换模型后旧运行仍归旧模型）。
- 运行记录 `input.source` 记触发来源：`chat / ui / api_key / schedule`（定时任务再带 `schedule_id`）。
- `run_nodes.started_at / finished_at` 由引擎写入，详情返回节点 `input / output / duration_ms`。
- `messages` 接口返回 `token_usage`。

### 3.3 新增接口

| 接口 | 用途 |
|---|---|
| `GET /stats/overview` | 工作台：资源计数、今日 / 7 日指标、待处理项、降级项、最近运行 |
| `GET /stats/runs/daily` | 按天趋势（分状态运行数、token、成本、平均耗时），缺失日期补零，可按类型 / 智能体 / 工作流过滤 |
| `GET /stats/runs/summary` | 时间窗汇总 |
| `GET /stats/models` / `/stats/agents` / `/stats/workflows` | 按模型 / 智能体 / 工作流聚合，含用量为 0 的对象 |
| `GET /runs/summary` 扩展 | 随列表筛选联动，新增 P50 / P95 / 成功率 / 耗时分布桶 |
| `GET /tools/{id}` / `POST /tools/{id}/toggle` | 工具详情（引用智能体）与启停；停用的工具不暴露给模型 |
| `POST /models/{id}/toggle` | 模型启停（admin，写审计） |
| `PUT /schedules/{id}` / `POST /schedules/{id}/run` / `GET /schedules/{id}` | 定时任务编辑、立即执行、详情；创建 / 编辑时 cron 非法 422 |
| `POST /users/{id}/reset-password` | 管理员重置密码 |
| `POST /workflows/{id}/duplicate` | 复制工作流 |
| `POST /knowledge-bases/{id}/documents/{doc_id}/reprocess` | 重新解析文档 |
| `GET /prompt-templates/{id}/agents` | 绑定该模板的智能体 |
| 10 个 `/batch` | agents（publish / delete）、models、tools、api-keys、schedules、users（enable / disable / delete）、workflows、knowledge-bases、prompt-templates（delete）、documents（delete / reprocess） |

列表补字段与筛选见 `04` 各节。
