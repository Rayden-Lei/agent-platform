# 智枢·智能体平台 运行与部署

版本 V2.1 · 2026-09-04

> 本地开发、环境变量、数据库初始化与迁移、两种部署形态、日志与排障。改了启动方式或配置项必须同批更新本文档。

## 1. 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| Python | 3.12+ | LangChain 1.x 需 3.10+；用 uv 管理虚拟环境与依赖 |
| Node.js | 20+ | 前端构建 |
| PostgreSQL | 16 + pgvector 扩展 | 推荐镜像 `pgvector/pgvector:pg16` |
| Redis | 7 | 只用于登录限流；不可用时限流静默关闭 |
| MinIO | 任意近期版本 | 知识库文档原文存储，桶不存在会自动创建 |
| tesseract | 可选 | 图片 OCR；未安装时图片文档解析为空文本 |

## 2. 本地开发

### 2.1 后端

```bash
cd backend
uv venv .venv --python 3.12
uv pip install --python .venv/bin/python -r requirements.txt pytest
cp .env.example .env            # 按第 3 节修改
PGPASSWORD=<密码> PGUSER=admin .venv/bin/python scripts/setup_db.py   # 建库 + vector 扩展，只需一次
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
curl http://127.0.0.1:8000/health
```

- 应用启动时会自动建缺失的表并创建 `admin / admin123`，`scripts/init_db.py` 只是同样逻辑的手动版本。
- `setup_db.py` 读 `PGHOST / PGPORT / PGUSER / PGPASSWORD / PGDATABASE` 环境变量，默认用户 `admin`、库 `agent_platform`。
- 验证导入：`.venv/bin/python -c "from app.main import app"`。

### 2.2 前端

```bash
cd frontend
npm install
npm run dev -- --port 18056 --host 0.0.0.0
```

Vite 把 `/api` 代理到 `http://127.0.0.1:8000`（`vite.config.ts`），所以后端要先起来。类型检查 `npx tsc --noEmit`，构建 `npm run build`。

### 2.3 连接共享数据服务时

`.env` 里的 `DATABASE_URL / REDIS_URL / MINIO_ENDPOINT` 可以指向远程服务，这样本地不用装数据库。此时要记住：

- 库里是别人也在用的数据，删表、清数据、批量更新前先确认。
- 每个连上这个库的后端进程都会加载并触发启用中的定时任务，本地跑后端或 pytest 时也会触发。
- `EMBEDDING_DIM` 必须与库里向量列的维度一致（查法见第 8 节）。

后端读 `backend/.env`（pydantic-settings，`extra=ignore`）；Docker Compose 读根目录 `.env` 再注入容器。

## 4. 数据库初始化与迁移

1. 首次：`setup_db.py` 建库与扩展 → 启动应用自动建表。
2. 之后每次拉取代码：查看 `backend/scripts/migrations/` 里有没有新脚本，按文件名顺序执行未跑过的：

```bash
cd backend
.venv/bin/python scripts/migrations/<文件名>.py          # 预览
.venv/bin/python scripts/migrations/<文件名>.py --apply  # 有破坏性操作的脚本需要显式 --apply
```

脚本幂等，重复执行无副作用。目前没有记录"已执行到哪个脚本"的表，靠人工核对；引入 Alembic 在演进路线里。

## 5. 测试

```bash
cd backend
PYTHONPATH=. .venv/bin/python -m pytest tests/ -v
```

- 测试连接 `.env` 指向的库，用 `admin / admin123` 登录，数据以 `pytest-` 前缀命名并自行清理。
- CI（`.github/workflows/ci.yml`）：后端在 Postgres + Redis 服务容器上跑 pytest；前端跑 `tsc --noEmit` 与 `vite build`。push 到 main 与 PR 触发。

## 6. 部署方式 A：Docker Compose

```bash
cp .env.example .env      # 根目录，改密码与密钥
docker compose up -d --build
```

| 容器 | 端口 | 说明 |
|---|---|---|
| api | 8000 | 后端，启动时等待数据库就绪、建表、初始化管理员 |
| web | 18056 → 80 | Nginx 托管前端静态文件，`/api/` 反代到 api:8000，关闭缓冲以支持 SSE |
| postgres | 5432 | 数据卷 `pgdata` |
| redis | 6379 | 无密码 |
| minio | 9000 / 9001 | 数据卷 `miniodata`，9001 是控制台 |

- 访问 `http://<主机>:18056`，登录 `admin / admin123`，首次登录后改密码。
- 更新：`git pull && docker compose up -d --build`；有新迁移脚本时 `docker compose exec api python scripts/migrations/<文件>.py --apply`。
- 停止 `docker compose down`；连数据一起清 `docker compose down -v`（不可逆）。
- `docker-compose.yml` 里的 `version` 字段已废弃，compose v2 会告警，可删。

## 7. 部署方式 B：裸机 uvicorn + 外部数据服务

适合已有 PostgreSQL / Redis / MinIO 的机器。

```bash
cd <仓库>/backend
uv venv .venv --python 3.12 && uv pip install --python .venv/bin/python -r requirements.txt
# 写好 .env（DATABASE_URL 等指向外部服务，REDIS_URL 带密码）
setsid nohup .venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000 >> uvicorn.log 2>&1 < /dev/null &
curl -s http://127.0.0.1:8000/health
```

重启（更新代码后）：

```bash
cd <仓库> && git pull --ff-only
cd backend && pkill -f 'uvicorn app.main'; sleep 2
setsid nohup .venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000 >> uvicorn.log 2>&1 < /dev/null &
tail -n 5 uvicorn.log
```

nohup 方式机器重启后不会自动拉起。建议改成 systemd：

```ini
# /etc/systemd/system/agent-platform.service
[Unit]
Description=Agent Platform API
After=network.target

[Service]
WorkingDirectory=/path/to/agent-platform/backend
ExecStart=/path/to/agent-platform/backend/.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

`systemctl enable --now agent-platform`，日志走 `journalctl -u agent-platform -f`。

前端：`npm run build` 后把 `frontend/dist` 交给任意静态服务器，并把 `/api/` 反代到 8000，配置参考 `frontend/nginx.conf`（注意 `proxy_buffering off`，否则 SSE 会被攒包）。

## 8. 日志与排障

### 8.1 日志

- 应用日志格式 `时间 级别 模块: 内容`，级别 INFO 起（`main.py` 里 `logging.basicConfig`）。
- 裸机方式在 `backend/uvicorn.log`；compose 方式 `docker compose logs -f api`；systemd 方式 `journalctl`。
- 调度器每次触发、工作流失败、对话失败、上下文构建失败都有日志且带 `run_id`。

### 8.2 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 上传文档后状态 failed，错误含 `expected N dimensions` | `EMBEDDING_DIM` 与列维度不一致 | 查列维度：`SELECT atttypmod FROM pg_attribute WHERE attrelid='document_chunks'::regclass AND attname='embedding'`；改配置或走迁移改列后重新处理文档 |
| 检索结果明显只按字面匹配 | embedding 接口不可用，静默退化为 hash 向量 | 检查 `EMBEDDING_API_BASE / KEY` 与网络；修好后重新处理文档（旧切片仍是 hash 向量） |
| 连续输错密码不锁定 | Redis 不可达或缺密码，限流静默关闭 | `REDIS_URL` 加密码；用 `redis.from_url(...).ping()` 验证 |
| 待审核的工作流重启后无法续跑 | checkpointer 在进程内存 | 重新运行；换 Postgres checkpointer 在演进路线 |
| 定时任务每次触发两条运行记录 | 两个后端进程连同一个库 | 只保留一个进程启用调度，或停用测试任务 |
| 对话报"模型不可用" | 模型被停用或智能体引用的模型被删 | 模型管理里检查 |
| 模型密钥解密失败 | `AES_KEY` 变了 | 恢复原 key；或重新录入所有模型密钥 |
| 前端 401 循环跳登录 | token 过期或 `SECRET_KEY` 变了 | 重新登录 |
| SSE 回复一次性整段出现 | 反向代理开了缓冲 | nginx `proxy_buffering off` |

### 8.3 快速自检脚本

```bash
cd backend && PYTHONPATH=. .venv/bin/python - <<'PY'
from sqlalchemy import text
from app.config import settings
from app.db.session import engine
with engine.connect() as c:
    dim = c.execute(text("SELECT atttypmod FROM pg_attribute WHERE attrelid='document_chunks'::regclass AND attname='embedding'")).scalar()
print("向量列维度", dim, "| 配置", settings.EMBEDDING_DIM, "| 一致", dim == settings.EMBEDDING_DIM)
import redis; print("Redis", redis.from_url(settings.REDIS_URL, socket_connect_timeout=3).ping())
from minio import Minio; print("MinIO 桶存在", Minio(settings.MINIO_ENDPOINT, access_key=settings.MINIO_ACCESS_KEY, secret_key=settings.MINIO_SECRET_KEY, secure=False).bucket_exists(settings.MINIO_BUCKET))
PY
```

## 9. 备份与恢复

- 数据库：`pg_dump -Fc agent_platform > backup.dump`；compose 下 `docker compose exec postgres pg_dump -U admin -Fc agent_platform`。恢复 `pg_restore -d agent_platform backup.dump`。
- 文档原文：MinIO 数据目录或桶级复制。
- 配置：`.env` 单独备份到仓库外，其中 `AES_KEY` 丢失等于丢失全部模型密钥。
