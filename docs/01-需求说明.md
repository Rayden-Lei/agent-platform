# 智枢·智能体平台 需求说明（SRS）

版本 V2.2 · 2026-09-04 · 与代码现状同步

> 本文档描述平台"做什么"。每条功能需求都标注实现状态，状态以代码为准，不以计划为准。
> 需求变更先改本文档，再改代码；实现状态变化时同批更新。

## 1. 文档目的与范围

- 目的：定义智能体中台的功能需求、非功能需求与验收标准，作为开发、测试与验收的共同依据。
- 范围：后端 API、前端控制台、部署形态。不含具体模型厂商的能力说明。
- 读者：开发者、测试、接入方（调用平台接口的其他系统）。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 智能体 Agent | 一组配置：系统提示词、模型、参数、可用知识库、可用工具。发布后才能对话 |
| 模型 Model | 一个 OpenAI 兼容协议的大模型接入点：地址、密钥、模型名、默认参数、单价 |
| 会话 Conversation / 消息 Message | 用户与某个智能体的一次多轮对话及其中每条消息 |
| 运行记录 Run | 一次对话回复或一次工作流执行的执行记录：状态、输入输出、token、耗时、错误 |
| 知识库 KB / 文档 Document / 切片 Chunk | 文档上传后被解析、切片、向量化，切片是检索的最小单元 |
| RAG | 检索增强生成：先从知识库检索相关切片，再把切片注入提示词让模型作答 |
| 工作流 Workflow | 用节点和连线编排的有向图，由 LangGraph 执行 |
| 工具 Tool | 智能体或工作流可调用的外部能力：内置工具或自定义 HTTP 接口 |
| SSE | Server-Sent Events，对话回复的流式推送方式 |
| 定时任务 ScheduledJob | 按 Cron 表达式定时触发某个工作流 |
| API Key | 供外部系统调用平台接口的长期凭据，与 JWT 共用 Bearer 头，以归属用户身份执行并按次扣配额 |

## 3. 用户角色与权限

三级角色，登录后由 JWT 携带，后端按路由校验。

| 角色 | 定位 | 能做什么 |
|---|---|---|
| admin 管理员 | 平台负责人 | 全部权限，含用户管理、审计日志、模型的增删改 |
| developer 开发者 | 搭建智能体的人 | 创建/编辑/发布智能体、工作流、知识库、工具；查看模型；查看运行记录；管理 API Key 与定时任务 |
| caller 调用者 | 只使用智能体的人 | 与已发布的智能体对话，管理自己的会话 |

权限矩阵（后端路由级校验的实际情况）：

| 模块 | admin | developer | caller |
|---|---|---|---|
| 登录、查看自己 | ✓ | ✓ | ✓ |
| 对话、会话（仅本人的） | ✓ | ✓ | ✓ |
| 智能体 | ✓ | ✓ | ✗ |
| 模型 查看 | ✓ | ✓ | ✗ |
| 模型 增删改、连通测试 | ✓ | 测试 ✓ / 增删改 ✗ | ✗ |
| 工具、知识库、工作流 | ✓ | ✓ | ✗ |
| 运行记录 | ✓ | ✓ | ✗ |
| API Key、定时任务 | ✓ | ✓ | ✗ |
| 用户管理、审计日志 | ✓ | ✗ | ✗ |

数据行级隔离目前只有两处：会话只能操作本人的；知识库按"公开 / 指定角色可见"过滤检索结果。其余资源在角色内全员可见，这是内部平台的有意取舍，见 `09-演进路线.md`。

## 4. 功能需求

状态说明：**已实现** 代码已有且可用；**部分实现** 有代码但链路未闭合；**规划** 尚未开始。

### 4.1 认证与用户

| 编号 | 名称 | 优先级 | 状态 | 说明 |
|---|---|---|---|---|
| FR-001 | 登录认证 | P0 | 已实现 | 用户名密码登录，签发 JWT，有效期由配置决定（默认 24 小时）。同一用户名连续 5 次失败锁定 10 分钟，计数存 Redis；Redis 不可用时限流静默关闭 |
| FR-002 | 角色权限 | P0 | 已实现 | 三级角色，路由级鉴权，见第 3 节权限矩阵 |
| FR-016 | 审计日志 | P0 | 已实现 | 记录登录成功/失败、模型创建/删除、智能体发布、对话中的知识库检索（含召回切片与鉴权剔除数）。管理员分页查看，可按动作、资源、用户名筛选 |
| FR-017 | API Key 管理 | P1 | 已实现 | 生成（明文仅返回一次，库中只存哈希）、列表、启用/禁用、删除，带配额与用量字段；调用方式见 FR-021 |
| FR-021 | API Key 鉴权调用 | P0 | 已实现 | 外部系统用 `Authorization: Bearer ak_...` 调用对话、会话、工作流运行接口，以 Key 归属用户的身份执行；每个请求扣 1 次配额，用尽返回 429；管理类接口不接受 API Key |

### 4.2 模型与智能体

| 编号 | 名称 | 优先级 | 状态 | 说明 |
|---|---|---|---|---|
| FR-003 | 模型管理 | P0 | 已实现 | 模型配置的增删改查、连通性测试、输入/输出单价（元/百万 token）。API 密钥 AES 加密入库，任何接口不回传密钥。被智能体引用的模型不能删除 |
| FR-004 | 模型统一接入 | P0 | 已实现 | 通过 LangChain ChatOpenAI 统一接入 OpenAI 兼容协议的厂商，流式输出并提取 token 用量 |
| FR-005 | 智能体配置 | P0 | 已实现 | 名称、描述、系统提示词、模型、参数、知识库列表、工具列表；配置存数据库 |
| FR-006 | 版本与发布 | P0 | 已实现 | 发布时版本号 +1 并保存配置快照；可查看版本历史并回滚到任一版本（回滚也产生新版本号） |

### 4.3 对话运行时

| 编号 | 名称 | 优先级 | 状态 | 说明 |
|---|---|---|---|---|
| FR-007 | 对话运行时 | P0 | 已实现 | 只能与已发布的智能体对话。SSE 流式逐 token 返回；多轮上下文保留最近 20 条消息，更早的由模型压缩成摘要；工具调用循环；RAG 引用注入与来源回填；支持停止（已生成部分落库，运行记录状态 cancelled）、重新生成、实时 token 展示 |
| FR-008 | 工具调用 | P0 | 已实现 | 内置工具：当前时间、四则计算器（AST 白名单求值）。自定义 HTTP 工具：URL、方法、固定请求头、超时 |

### 4.4 知识库与检索

| 编号 | 名称 | 优先级 | 状态 | 说明 |
|---|---|---|---|---|
| FR-009 | 知识库管理 | P0 | 已实现 | 创建、编辑、删除知识库；切片大小与重叠；访问权限：公开或仅指定角色可见，权限变更递增策略版本号 |
| FR-010 | 文档处理 | P0 | 已实现 | 上传文件存 MinIO，后台异步处理，状态流转 uploading → parsing → chunking → ready / failed。按类型解析分片：txt 按段落、Markdown 按标题层级、PDF 按页、Word 按段落保留标题、CSV/XLSX 按行保留列名、图片走 tesseract OCR。向量化走 OpenAI 兼容 embedding 接口，未配置或调用失败时退化为 hash 向量 |
| FR-011 | 检索增强 | P0 | 已实现 | 向量相似度与关键词两路召回，RRF 倒排融合，词法覆盖率重排，低分与断崖淘汰；权限先过滤后召回，重排后逐条再鉴权。对话侧先由模型把问题改写成 3 个子查询分别检索再合并；提示词要求回答标注片段编号且不得编造 |

### 4.5 工作流

| 编号 | 名称 | 优先级 | 状态 | 说明 |
|---|---|---|---|---|
| FR-012 | 工作流编排 | P0 | 已实现 | React Flow 拖拽画布。10 类节点：开始、结束、智能体、工具、条件、知识库检索、代码执行、HTTP 请求、循环、人工审核。节点可配置输入引用与输出字段提取；条件节点按 true/false 分支，循环节点按次数或表达式回环。编辑器内可直接测试运行（不落库） |
| FR-013 | 工作流运行 | P0 | 已实现 | LangGraph 执行，每个节点写运行日志。人工审核节点暂停等待，管理端通过/拒绝后续跑。运行记录含状态、输入输出、错误、开始/结束时间与耗时 |
| FR-014 | 工具管理 | P0 | 已实现 | 工具的增删改查与测试调用 |
| FR-018 | 定时调度 | P1 | 已实现 | 按 Cron 表达式定时触发工作流，记录最近触发时间；可启停。调度器在进程内运行，多实例部署会重复触发 |

### 4.6 监控与运维

| 编号 | 名称 | 优先级 | 状态 | 状态说明 |
|---|---|---|---|---|
| FR-015 | 运行监控 | P0 | 已实现 | 运行记录分页列表，可按类型与状态筛选；顶部统计由接口全库聚合；详情含输入输出、节点日志、token、按模型单价折算的成本、耗时；待审核的运行可在此通过或拒绝 |
| FR-019 | 自动化测试 | P1 | 已实现 | pytest 用例覆盖认证、模型、智能体、工具、知识库、工作流、运行记录收尾、API Key 鉴权 |
| FR-020 | CI | P1 | 已实现 | GitHub Actions：后端 pytest（带 Postgres/Redis 服务）+ 前端类型检查与构建 |
| FR-022 | 列表分页 | P0 | 已实现 | 除会话消息外全部列表接口服务端分页，`page / page_size`（上限 100）+ `{items, total, page, page_size}`；筛选下推；契约见 `04-接口设计.md` 2.3 |
| FR-023 | 请求追踪 | P0 | 已实现 | 每个请求分配 `X-Request-Id`，贯穿日志、响应头与错误体 `trace_id`；调用方可自带；每请求一条访问日志（方法/路径/状态码/耗时） |
| FR-024 | 降级状态可见 | P0 | 已实现 | `GET /system/status` 汇总降级项（向量后端、登录限流、数据库、调度器）；`/health` 报 `embedding_mode`；切片 `meta` 记录入库时的向量后端；知识库页顶部告警 |

## 5. 非功能需求

| 编号 | 类别 | 要求 | 现状 |
|---|---|---|---|
| NFR-001 | 性能 | 50 并发对话；不含模型延迟的首字时间 < 3 秒 | 未压测。对话前的 RAG 查询改写会多一次模型调用 |
| NFR-002 | 安全 | 密码 bcrypt 哈希；模型密钥 AES 加密；JWT 鉴权；登录限流；操作审计；日志与接口不泄露密钥 | 已实现。代码执行节点与 HTTP 节点无沙箱与目标白名单，仅限内部可信用户使用 |
| NFR-003 | 部署 | Docker Compose 一键私有化；或裸机 uvicorn + 外部数据服务 | 两种方式都可用，见 `08-运行与部署.md` |
| NFR-004 | 可用性 | 启动自动建表与初始化管理员；文档处理与定时任务异步不阻塞接口 | 已实现。人工审核的中断状态存于进程内存，后端重启后丢失 |
| NFR-005 | 可维护性 | 分层清晰；有自动化测试与 CI；文档与代码同步 | 已实现 |
| NFR-006 | 可观测性 | 应用日志可查；运行记录完整；错误不静默；降级可见 | 已实现：日志带请求追踪 ID、每请求一条访问日志、宽泛异常捕获全部留痕、降级状态经 `/system/status` 汇报 |
| NFR-007 | 可扩展性 | 模型、工具、工作流节点可按约定新增；数据库为唯一配置源 | 已实现，扩展方式见 `06-后端规范.md` |

## 6. 验收标准

| 编号 | 标准 |
|---|---|
| AC-001 | 三种角色登录后菜单与接口权限符合权限矩阵；连续 5 次错误密码后被锁定 10 分钟 |
| AC-002 | 配置模型并测试连通成功；对话产生的 token 与成本在运行记录中可见 |
| AC-003 | 发布智能体产生版本快照；回滚后配置恢复到该快照 |
| AC-004 | 对话流式输出、多轮记忆、工具调用、引用来源、停止、重新生成均正常；停止后刷新页面仍能看到已生成的部分回答 |
| AC-005 | 上传各类型文档后状态到达 ready；检索评测页能看到命中切片、分数与关键词；非公开知识库对无权角色不可检索 |
| AC-006 | 拖拽编排含条件分支与人工审核的工作流并运行，节点日志完整；审核通过后续跑到结束 |
| AC-007 | 审计日志记录关键操作；API Key 可生成并能以 Bearer 头调用对话接口，配额用尽返回 429；定时任务按 Cron 触发并留下运行记录 |
| AC-008 | pytest 全部通过；Docker Compose 在干净环境一键拉起并可登录 |
| AC-009 | 任一错误响应都带 `trace_id`，用它能在日志中检索到该次请求的全部记录；未处理异常返回 500 且不外泄堆栈 |
| AC-010 | 未配置向量模型时，`/health` 报 `embedding_mode=hash`，`/system/status` 的 `degraded` 点名 embedding，知识库页顶部有告警 |
