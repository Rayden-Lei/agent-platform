# 智枢·智能体平台 数据库设计（DBD）

版本 V2.2 · 2026-09-04 · 以 `backend/app/db/models.py` 为准

> ORM 模型是表结构的唯一定义；本文档解释含义、约束与演进方式。改表必须同批：改 `models.py`、写迁移脚本、更新本文档。

## 1. 通用约定

| 项 | 约定 |
|---|---|
| 主键 | `id BIGSERIAL`，接口以数字传输（见接口文档第 2.4 节） |
| 时间 | `timestamptz`，数据库 `now()` 默认值；接口输出 ISO 8601 带时区 |
| JSON | `jsonb`，默认 `{}` 或 `[]`，不为 NULL |
| 向量 | pgvector `vector(N)`，N 取配置 `EMBEDDING_DIM`；**列维度一旦建好就固定**，换维度必须迁移 |
| 审计列 | 配置类表有 `created_at / updated_at`（`TimestampMixin`），部分有 `created_by`；只增不改的日志类表只有 `created_at` |
| 外键删除语义 | 配置类之间的引用 `RESTRICT`：被引用的模型、工作流、用户不能删；运行类数据 `CASCADE`：删智能体、工作流、知识库、用户时其运行数据级联删除；审计日志 `SET NULL` 保留记录 |
| 建表方式 | 应用启动时 `Base.metadata.create_all` 只建缺失的表，不改已有列；列级变更靠 `scripts/migrations/` |

## 2. 表关系概览

```
users ─┬─< models ─────< agents >───── workflows ─┬─< workflow_nodes（未使用）
       │                 │  │                     ├─< scheduled_jobs
       │                 │  ├──< agent_versions   └─< runs ─< run_nodes
       │                 │  └──○ agent_shares（一个智能体至多一条）─< conversations / runs（share_id）
       ├─< knowledge_bases ─< documents ─< document_chunks
       ├─< conversations ─< messages
       ├─< runs
       ├─< api_keys
       └─< audit_logs（SET NULL）
tools（独立表，智能体通过 agents.tool_ids JSON 引用，工作流通过节点配置里的 tool_name 引用）
```

## 4. JSON 字段结构

### 4.1 agents.params / models.default_params

```json
{"temperature": 0.7, "max_tokens": 2048, "top_p": 0.9, "thinking": "disabled"}
```
两列同一结构（`schemas.ModelParams`），只认这四个键，未知键 422；取值 temperature 0～2、top_p 0～1、max_tokens 1～128000、`thinking` 取 `disabled / enabled`。只存设置了的键，没设置的键继承上一层。

运行时生效参数 = `models.default_params` ← `agents.params` 逐键覆盖（`gateway.effective_params`，值为空的键不覆盖）；对话、工作流智能体节点都按此构造模型，摘要与连通测试只用模型默认。2026-09-25 前 `agents.params` 从未生效，表单却写着"透传"。
`thinking` 不设 = 跟随模型默认，网关按 OpenAI 兼容扩展 `extra_body.thinking.type` 透传给 DeepSeek 类混合推理模型；关闭思考模式首字节明显更快。
模型实例按 (模型 id, updated_at, 生效参数) 缓存：共用一个模型、参数不同的智能体各用各的实例，改模型配置才淘汰旧实例。

### 4.2 tools.config（http）

```json
{"url": "https://api.example.com/weather", "method": "GET", "headers": {"Accept": "application/json"},
 "parameters": {"type": "object",
                "properties": {"city": {"type": "string", "description": "城市名", "enum": ["北京", "上海"]},
                               "days": {"type": "integer", "description": "预报天数"}},
                "required": ["city"]}}
```
凭据不放 headers（保存时 422）：走 `tools.auth` + `tools.secret_enc`，执行时按方式拼成 Authorization 头、自定义请求头或查询参数（2026-09-29 起；此前 headers 里的 Token 明文存储、原样返回给所有 admin / developer）。

`parameters` 是参数声明（FR-030），JSON Schema 子集：顶层固定 `object`；`type` 只允许 `string / number / integer / boolean`，不支持嵌套对象与数组；`enum` 只对 string 有效；参数名匹配 `^[A-Za-z_][A-Za-z0-9_]*$`，最多 20 个；`required` 必须是 `properties` 的子集。保存时按此校验（422）并规范化（补 `type / required`，去掉空的 `enum`）。未声明或 `properties` 为空的工具是无参数工具，只接受 `{}`。

### 4.3 workflows.graph

```json
{
  "nodes": [
    {"id": "start_1", "type": "start", "config": {}, "position": {"x": 80, "y": 80}},
    {"id": "node_1", "type": "tool", "config": {"tool_name": "calculator", "input_ref": "{{input}}", "output_field": "result"}, "position": {"x": 300, "y": 80}},
    {"id": "end_1", "type": "end", "config": {}, "position": {"x": 520, "y": 80}}
  ],
  "edges": [
    {"from": "start_1", "to": "node_1"},
    {"from": "node_1", "to": "end_1"}
  ]
}
```
条件节点出边 `when` 取 `true / false`；循环节点出边 `when` 取 `loop / exit`。各节点 `config` 字段见 `02-架构设计.md` 第 4.4 节。

并行（FR-029）：`parallel` 节点 `config` 为空对象，出边 ≥ 2 条且不带 `when`，每条出边开始一条线性分支；分支末节点都连到同一个 `join` 节点。保存时按 `workflow/validation.validate_graph` 校验，不合法 400。示例：

```json
{"nodes": [{"id": "s", "type": "start", "config": {}}, {"id": "par", "type": "parallel", "config": {}},
           {"id": "a", "type": "code", "config": {"code": "result = 'A'"}}, {"id": "b", "type": "http", "config": {"url": "https://...", "method": "GET"}},
           {"id": "join", "type": "join", "config": {}}, {"id": "e", "type": "end", "config": {}}],
 "edges": [{"from": "s", "to": "par"}, {"from": "par", "to": "a"}, {"from": "par", "to": "b"},
           {"from": "a", "to": "join"}, {"from": "b", "to": "join"}, {"from": "join", "to": "e"}]}
```

`run_nodes.node_type` 相应新增取值 `parallel`、`join`。

### 4.4 document_chunks.meta

```json
{
  "type": "pdf", "page": 3, "index": 7,
  "kb_id": 1, "doc_id": 5, "is_public": true, "visible_roles": [], "policy_version": 1,
  "embedding_mode": "hash", "embedding_model": "hash-fallback", "embedding_dim": 1024
}
```
解析类字段按文件类型不同：`page`（PDF）、`row`（表格）、`heading / style`（Word）、`headings`（Markdown）。权限类字段是入库时的快照，改权限不回写，只供审计；检索鉴权读 `knowledge_bases` 的当前值（2026-09-25 起）。

向量类字段记录**这批切片实际是用什么向量化的**：`embedding_mode` 取 `model`（真实向量模型）或 `hash`（本地兜底）。
换模型或从降级恢复后，据此筛出需要重新处理的文档；没有这三个字段时只能全库重建。存量切片（2026-09-04 之前入库）没有这些字段。

## 8. 注意事项

- **向量维度**：`EMBEDDING_DIM` 与 `document_chunks.embedding` 列维度必须一致，否则入库与检索直接报错。换向量模型的流程：改配置 → 迁移脚本改列 → 重新处理全部文档。
- **共享数据库**：开发环境与服务器可能共用同一库；任何删表、清数据、批量更新前先确认影响面。
- **AES_KEY**：决定 `models.api_key_enc` 能否解密，部署后不要改；必须改时要先导出明文重新加密。
- **定时任务多实例**：每个连接同一库的后端进程都会加载并触发启用中的定时任务；本地开发时留意不要重复触发线上任务。
