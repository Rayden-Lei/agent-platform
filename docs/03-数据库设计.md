# 智枢·智能体平台 数据库设计（DBD）

版本 V2.2 · 2026-09-04 · 以 `backend/app/db/models.py` 为准

> ORM 模型是表结构的唯一定义；本文档解释含义、约束与演进方式。改表必须同批：改 `models.py`、写迁移脚本、更新本文档。

## 1. 通用约定

| 项 | 约定 |
|---|---|
| 主键 | `id BIGSERIAL`，接口以数字传输（见接口文档第 2.4 节） |
| 时间 | `timestamptz`，数据库 `now()` 默认值；接口输出 ISO 8601 带时区 |
| JSON | `jsonb`，默认 `{}` 或 `[]`，不为 NULL |
| 向量 | pgvector `vector(N)`，N 取配置 `EMBEDDING_DIM`；**列维度一旦建好就固定**，换维度必须迁移 |
| 审计列 | 配置类表有 `created_at / updated_at`（`TimestampMixin`），部分有 `created_by`；只增不改的日志类表只有 `created_at` |
| 外键删除语义 | 配置类之间的引用 `RESTRICT`：被引用的模型、工作流、用户不能删；运行类数据 `CASCADE`：删智能体、工作流、知识库、用户时其运行数据级联删除；审计日志 `SET NULL` 保留记录 |
| 建表方式 | 应用启动时 `Base.metadata.create_all` 只建缺失的表，不改已有列；列级变更靠 `scripts/migrations/` |

## 2. 表关系概览

```
users ─┬─< models ─────< agents >───── workflows ─┬─< workflow_nodes（未使用）
       │                 │  │                     ├─< scheduled_jobs
       │                 │  └──< agent_versions   └─< runs ─< run_nodes
       ├─< knowledge_bases ─< documents ─< document_chunks
       ├─< conversations ─< messages
       ├─< runs
       ├─< api_keys
       └─< audit_logs（SET NULL）
tools（独立表，智能体通过 agents.tool_ids JSON 引用，工作流通过节点配置里的 tool_name 引用）
```

## 4. JSON 字段结构

### 4.1 agents.params / models.default_params

```json
{"temperature": 0.7, "max_tokens": 2048, "top_p": 0.9}
```
只有 `models.default_params` 生效；`agents.params` 预留。

### 4.2 tools.config（http）

```json
{"url": "https://api.example.com/search", "method": "POST", "headers": {"Authorization": "Bearer ..."}}
```
注意 headers 里的凭据是明文存储，目前没有加密；见演进路线。

### 4.3 workflows.graph

```json
{
  "nodes": [
    {"id": "start_1", "type": "start", "config": {}, "position": {"x": 80, "y": 80}},
    {"id": "node_1", "type": "tool", "config": {"tool_name": "calculator", "input_ref": "{{input}}", "output_field": "result"}, "position": {"x": 300, "y": 80}},
    {"id": "end_1", "type": "end", "config": {}, "position": {"x": 520, "y": 80}}
  ],
  "edges": [
    {"from": "start_1", "to": "node_1"},
    {"from": "node_1", "to": "end_1"}
  ]
}
```
条件节点出边 `when` 取 `true / false`；循环节点出边 `when` 取 `loop / exit`。各节点 `config` 字段见 `02-架构设计.md` 第 4.4 节。

### 4.4 document_chunks.meta

```json
{
  "type": "pdf", "page": 3, "index": 7,
  "kb_id": 1, "doc_id": 5, "is_public": true, "visible_roles": [], "policy_version": 1,
  "embedding_mode": "hash", "embedding_model": "hash-fallback", "embedding_dim": 1024
}
```
解析类字段按文件类型不同：`page`（PDF）、`row`（表格）、`heading / style`（Word）、`headings`（Markdown）。权限类字段是入库时的快照。

向量类字段记录**这批切片实际是用什么向量化的**：`embedding_mode` 取 `model`（真实向量模型）或 `hash`（本地兜底）。
换模型或从降级恢复后，据此筛出需要重新处理的文档；没有这三个字段时只能全库重建。存量切片（2026-09-04 之前入库）没有这些字段。

### 4.5 runs.output（workflow）

```json
{"output": {"result": 42}, "steps": ["tool:calculator"]}
```
等待审核时：
```json
{"interrupt": {"node_id": "review_1", "instruction": "请审核", "data": "..."}, "steps": ["agent:客服"]}
```

## 7. 迁移管理

- 新表：加到 `models.py`，应用启动自动创建；仍建议写一份迁移脚本以便记录。
- 改列、加索引、数据修复：**必须**写 `backend/scripts/migrations/<YYYYMMDD_HHMMSS>_<随机后缀>_<描述>.py`。
- 脚本要求：模块级 docstring 写明改什么、为什么、影响、执行后是否需要额外操作；幂等可重复执行（`IF NOT EXISTS`、条件更新）；有破坏性操作的默认预览、加 `--apply` 才执行。
- 执行：`cd backend && .venv/bin/python scripts/migrations/<文件>.py`，读 `.env` 的 `DATABASE_URL`。没有自动执行机制，部署时人工按文件名顺序执行未跑过的脚本。

## 8. 注意事项

- **向量维度**：`EMBEDDING_DIM` 与 `document_chunks.embedding` 列维度必须一致，否则入库与检索直接报错。换向量模型的流程：改配置 → 迁移脚本改列 → 重新处理全部文档。
- **共享数据库**：开发环境与服务器可能共用同一库；任何删表、清数据、批量更新前先确认影响面。
- **AES_KEY**：决定 `models.api_key_enc` 能否解密，部署后不要改；必须改时要先导出明文重新加密。
- **定时任务多实例**：每个连接同一库的后端进程都会加载并触发启用中的定时任务；本地开发时留意不要重复触发线上任务。
