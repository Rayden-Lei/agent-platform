# 智枢·智能体平台 开发规范与铁律

版本 V1.0

> 本文档是项目开发的红线规范，所有后续开发必须遵守。铁律为最高优先级，一旦违反即为事故，必须返工。

## 第一部分 通用铁律（最高优先级）

### 铁律 1 文件操作
- 修改任何文件前，必须先 read 完整文件内容，再用 edit 精准替换。
- 严禁 read 只读前 N 行 + write 回写——这会截断文件，静默删除其余代码。
- 本项目曾因此删掉 runs.py 的 get 接口，导致 404，是严重事故。

### 铁律 2 工具调用参数
- 调用 get_goal、job_list 等无参工具时，必须传空对象 {}，否则报 binding 错误。
- 代码中自定义变量名不得与全局 tools 对象重名。

### 铁律 3 模板字符串
- 编写 TS 模板字符串时注意反引号与美元符号的转义；TSX 中优先用字符串拼接。

### 铁律 4 测试脚本
- 复杂 JSON 请求禁止用 shell -c 内联（引号转义地狱）。
- 一律写 .py 脚本文件再运行，用 httpx 加真实 Python 变量。

### 铁律 5 改完必验
- 每次改动后立即验证：后端跑 import 和接口 curl，前端跑 tsc --noEmit。
- 验证通过才算完成。

### 铁律 6 不重复造轮子
- 能用成熟框架就不自研。已确定：FastAPI、SQLAlchemy 2.0、LangChain、LangGraph、React、Ant Design、React Flow、pgvector。

## 第二部分 前端规范

### 规范 1 布局自适应
- 布局一律用 flex + height 100% 自适应，禁止写死 calc 高度。
- 顶栏固定高度 + flexShrink 0，内容区 flex 1 + minHeight 0。
- 全局 html body root 加 overflow-x hidden 兜底。
- 用户已反馈：写死高度导致 100% 缩放出滚动条，是已犯过的错。

### 规范 2 表格布局
- 列表页统一：页面 flex column，标题区 flexShrink 0，表格包在 fixed-table-wrapper 里，表体内部滚动，分页固定底部。
- 用户已要求：分页固定底部、表格内部滚动、页面不整体滚动。

### 规范 3 配色
- 主色 #1e40af 深蓝，侧边栏 #1f2937 深灰，背景 #f5f6f8。
- 禁止紫色系渐变（一股 AI 味道，用户明确反感）。
- 配色克制、专业、企业风，纯色优先。

### 规范 4 品牌
- 产品名固定为「智枢·智能体平台」，左上角 logo 文案不得改动。

### 规范 5 设计感
- 卡片圆角 + 细边框 + 轻阴影 + hover 上浮；表头浅灰底；状态用语义色 Tag；空状态用 Empty。禁止裸组件堆砌。

### 规范 6 移动端适配
- useBreakpoint 判断移动端，侧边栏收 Drawer + 汉堡按钮，表格横向滚动。

### 规范 7 技术栈
- React 18、TypeScript、Vite、Ant Design 5、React Router 6、Zustand、axios、React Flow。

## 第三部分 后端规范

### 规范 1 分层结构
- api 路由、services 业务、core 安全鉴权异常、db 模型会话、model_gateway 模型、rag 知识库、workflow 工作流、tools 工具、tasks 任务。
- 路由只做参数校验和编排，业务逻辑下沉到能力层。

### 规范 2 框架
- FastAPI + SQLAlchemy 2.0 + Alembic；模型用 LangChain ChatOpenAI；agent 用 create_agent；工作流用 LangGraph StateGraph。

### 规范 3 安全
- 密码 bcrypt 哈希；密钥 AES 加密；JWT + 三角色鉴权；接口返回密钥脱敏；日志不落密钥密码 token。

### 规范 4 数据库
- 14 张表，主键 BIGSERIAL，时间 timestamptz，JSON 用 jsonb，向量用 pgvector。
- 配置类删除 RESTRICT，运行类 CASCADE。数据库为唯一配置源。

### 规范 5 接口
- REST + JSON，前缀 /api/v1，统一 code message data，分页 page page_size，鉴权 Bearer，流式 SSE，错误码 401 403 404 422 500 504。

### 规范 6 异步与可观测
- 耗时任务走后台异步；运行记录落 runs，节点日志落 run_nodes，token 埋点。

## 第四部分 开发流程规范

1. 对照 docs 开发文档开发，需求变更先更新文档。
2. 每完成一个功能点立即验证。
3. 修改已有功能前先 read 相关文件。
4. 前后端联调用真实数据。
5. 文档、代码、验证结果三者齐全才算完成。

## 附：本项目已犯过的错（引以为戒）

1. read 限行 + write 回写，文件被截断。
2. 页面高度写死 calc，100% 缩放出滚动条。
3. 表格随页面整体滚动。
4. 配色用渐变紫，用户反馈一股 AI 味道。
5. 工具调用不传空对象、变量名与 tools 冲突。
6. shell -c 内联复杂 JSON，转义失败。
