# 智枢·智能体平台 接口设计（API）

版本 V2.1 · 2026-09-04 · 以 `backend/app/api/v1/` 为准

> 本文档是前后端与外部调用方的契约。改接口必须同批更新：路由代码、`frontend/src/api/index.ts`、本文档。
> 标注"规划"的小节是已定稿但尚未实现的契约，实现时按此执行，不得另起一套。

## 1. 基础约定

| 项 | 约定 |
|---|---|
| 前缀 | `/api/v1`；健康检查 `GET /health` 无前缀 |
| 协议 | REST + JSON；文件上传 `multipart/form-data`；对话回复 SSE |
| 鉴权 | `Authorization: Bearer <JWT>`；除登录与健康检查外全部需要 |
| 字符集 | UTF-8 |
| 时间 | ISO 8601 带时区字符串，例 `2026-09-04T03:57:56.476194+00:00` |
| 交互式文档 | FastAPI 自带 `/docs`，生产环境应关闭 |

## 2. 响应结构

### 2.1 成功

直接返回数据体，不套信封：单个资源返回对象，列表返回数组。

```json
{"id": 1, "name": "客服助手", "status": "published"}
```

三类例外，历史沿用，不再扩散到新接口：

- 删除类接口返回 `{"code": 0, "message": "ok"}`。
- 模型连通测试、工具测试返回 `{"code": 0, "message": "ok", "data": {...}}`。
- 上传文档返回精简对象 `{id, kb_id, name, file_type, status}`。

### 2.2 失败

HTTP 状态码表达错误类别，响应体固定 `{"detail": ...}`。

| 状态码 | 含义 | detail |
|---|---|---|
| 400 | 业务前置条件不满足 | 字符串，可直接展示，如"模型不可用" |
| 401 | 未登录或 token 失效 | 字符串；前端收到后清除凭据并跳登录 |
| 403 | 无权限、账号停用、智能体未发布 | 字符串 |
| 404 | 资源不存在或不属于当前用户 | 字符串 |
| 409 | 冲突：重名、被引用无法删除 | 字符串 |
| 422 | 请求体校验失败 | FastAPI 生成的数组，逐字段说明 |
| 429 | 登录失败次数过多 | 字符串 |
| 500 | 未捕获异常 | 框架默认文本；服务端日志有堆栈 |

业务异常由服务层抛 `BizError(status_code, detail)`，全局处理器转成上述结构。没有独立的业务错误码，前端按 HTTP 状态码与 detail 文案处理。

### 2.3 分页（FR-022）

除会话消息外，所有列表接口都是服务端分页，参数与响应结构统一：

```
GET /runs?page=1&page_size=20&status=failed&run_type=chat
```

| 参数 | 说明 |
|---|---|
| page | 从 1 起，默认 1 |
| page_size | 默认 20，上限 100，超出按 100 |
| 其余 | 各接口自己的筛选字段，全部在服务端生效 |

```json
{"items": [...], "total": 1234, "page": 1, "page_size": 20}
```

排序固定为 `id` 倒序（运行记录、审计、API Key、定时任务、会话按更新时间）或 `id` 正序（配置类），都带 `id` 作副键保证翻页稳定。空结果 `items` 为 `[]`。筛选参数全部在服务端生效，枚举型参数取值非法返回 422。

会话消息 `GET /conversations/{id}/messages` 是唯一例外：对话页需要整段历史，返回数组。前端下拉框取 `page_size=100` 的第一页（`OPTIONS_PAGE`），超过 100 项时要改为带 `q` 的服务端搜索，见演进路线。

### 2.4 ID 类型

主键以 JSON 数字传输。前端按 `number` 处理，比较用 `===`。平台内部 ID 远小于 2^53，暂不改为字符串；如引入雪花 ID 等长整型，必须全链路切换为字符串。

## 3. 认证与鉴权

### 3.1 JWT

`POST /auth/login` 返回的 token 有效期由 `ACCESS_TOKEN_EXPIRE_MINUTES` 决定（默认 1440 分钟）。payload：`sub` 用户 ID 字符串、`role`、`exp`。每次请求都会查库确认用户存在且启用，停用立即生效。

### 3.2 角色

| 依赖 | 允许 |
|---|---|
| `get_current_user` | 任何已登录用户 |
| `require_roles("admin")` | 管理员 |
| `require_roles("admin", "developer")` | 管理员与开发者 |

各接口的角色要求见第 4 节。

### 3.3 API Key 调用（FR-021）

- 请求头复用 `Authorization: Bearer ak_xxx`。`get_current_user` 按 `ak_` 前缀分流到 `api_key_service.authenticate`：查 `api_keys.key_hash = sha256(明文)`，要求 `is_enabled`；再校验归属用户存在且启用；最后用带前置条件的 `UPDATE ... WHERE used < quota` 扣 1 次配额并更新 `last_used_at`。
- 通过后以 Key 归属用户的身份与角色执行，等同于该用户登录。**每个通过鉴权的请求消耗 1 次配额**，与业务是否成功无关。
- 错误：401 "API Key 无效或已停用"；403 "API Key 归属账号不可用"；429 "API Key 配额已用尽"（不再累加 used）。
- 可用范围：所有只要求登录的接口（`/auth/me`、`/agents/{id}/chat`、`/conversations*`），以及显式开放的 `POST /workflows/{id}/run` 与 `POST /workflows/{id}/runs/{run_id}/resume`。其余管理接口对 API Key 返回 403 "API Key 不能访问管理接口"。
- 开放新的执行类接口给 API Key：路由依赖改为 `require_roles(..., allow_api_key=True)`，并在本节登记。

## 5. 对话 SSE 事件契约

响应头 `Content-Type: text/event-stream`，每个事件一行 `data: <JSON>` 加空行。事件顺序：`citations` → 若干 `delta` / `tool_call` / `tool_result` → `done`；任何阶段可能以 `error` 结束。

| type | 字段 | 说明 |
|---|---|---|
| citations | `citations: [{kb_id, chunk_id, doc_name, content, score}]` | 首个事件；无知识库时为空数组 |
| delta | `content` | 回复文本增量 |
| tool_call | `id, name, arguments` | 模型决定调用工具；`arguments` 为解析后的对象，解析失败为 `{"_raw": 字符串}` |
| tool_result | `tool_call_id, content` | 工具返回，截断 200 字符 |
| done | `message_id, run_id, conversation_id, usage: {prompt_tokens, completion_tokens, total_tokens}` | 正常结束 |
| error | `message` | 出错结束；此时运行记录已置 failed |

客户端主动断开（停止按钮）不会收到 `done`；服务端把已生成内容落库，运行记录置 `cancelled`。

前端解析器在 `frontend/src/api/index.ts` 的 `chatAgentStream`，新增事件类型时两端同批改。

## 6. 契约演进规则

- 改字段名、类型、枚举值：一次改到底，同批改路由、服务、前端 api 层与页面、本文档；不留 `新字段 || 旧字段` 兼容。
- 新增可选字段可以只加不删；删除字段先全仓搜索引用为零。
- 有第二个消费者（API Key 调用方）之后，破坏性变更要在本文档记录废弃时间。
