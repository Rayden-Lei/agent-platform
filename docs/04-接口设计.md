# 智枢·智能体平台 接口设计（API）

版本 V2.2 · 2026-09-04 · 以 `backend/app/api/v1/` 为准

> 本文档是前后端与外部调用方的契约。改接口必须同批更新：路由代码、`frontend/src/api/<域>.ts`（`index.ts` 只做 re-export）、本文档。
> 标注"规划"的小节是已定稿但尚未实现的契约，实现时按此执行，不得另起一套。

## 1. 基础约定

| 项 | 约定 |
|---|---|
| 前缀 | `/api/v1`；健康检查 `GET /health` 无前缀 |
| 协议 | REST + JSON；文件上传 `multipart/form-data`；对话回复 SSE |
| 鉴权 | `Authorization: Bearer <JWT>`；除登录与健康检查外全部需要 |
| 字符集 | UTF-8 |
| 时间 | ISO 8601 带时区字符串，例 `2026-09-04T03:57:56.476194+00:00` |
| 追踪 ID | 每个响应都带 `X-Request-Id` 头；调用方可用同名请求头指定（限 `[A-Za-z0-9._-]{1,64}`，非法值被忽略并另行生成） |
| 交互式文档 | FastAPI 自带 `/docs`，生产环境应关闭 |

## 2. 响应结构

### 2.1 成功

直接返回数据体，不套信封：单个资源返回对象，列表返回数组。

```json
{"id": 1, "name": "客服助手", "status": "published"}
```

三类例外，历史沿用，不再扩散到新接口：

- 删除类接口返回 `{"code": 0, "message": "ok"}`。
- 模型连通测试、工具测试返回 `{"code": 0, "message": "ok", "data": {...}}`。
- 上传文档返回精简对象 `{id, kb_id, name, file_type, status}`。

### 2.2 失败

HTTP 状态码表达错误类别，响应体固定 `{"detail": ..., "trace_id": "<X-Request-Id>"}`。

```json
{"detail": "工作流不存在", "trace_id": "1de7aa9bfeef4a18"}
```

| 状态码 | 含义 | detail |
|---|---|---|
| 400 | 业务前置条件不满足 | 字符串，可直接展示，如"模型不可用" |
| 401 | 未登录、token 失效，或登录账号已停用 / 不存在（"账号已停用或不存在，请重新登录"，2026-10-05 起，此前是 403 "账号不可用"，前端停在原页面一直报错） | 字符串；前端收到后清除凭据，带上当前页（`redirect`）与原因跳登录，登录后回到原页面（`15` OP-02） |
| 403 | 无权限、API Key 的归属账号停用、智能体未发布、来源 IP 命中黑名单（detail 固定"来源 IP 被拒绝"，由中间件在路由之前返回，`/health` 不受影响） | 字符串 |
| 404 | 资源不存在或不属于当前用户 | 字符串 |
| 409 | 冲突：重名、被引用无法删除 | 字符串 |
| 422 | 请求体校验失败 | FastAPI 生成的数组，逐字段说明（此响应无 `trace_id`，追踪 ID 见响应头） |
| 429 | 登录失败次数过多、API Key 配额用尽、入口限流（按 API Key / 登录用户 / 登录接口来源 IP 每分钟计数） | 字符串；限流的 429 另带响应头 `Retry-After`（秒）、`X-RateLimit-Limit`、`X-RateLimit-Remaining: 0` |
| 500 | 未捕获异常 | 固定文案"服务器内部错误，请携带 trace_id 联系管理员"；堆栈只进服务端日志，不外泄 |
| 503 | 模型熔断中：该模型连续失败达 `MODEL_BREAKER_FAIL_THRESHOLD` 次，`MODEL_BREAKER_OPEN_SECONDS` 内不请求上游直接失败 | 字符串"模型「x」暂时不可用（熔断中，N 秒后自动重试）"，带 `Retry-After`；对话接口以 SSE `error` 事件下发同一文案，工作流运行记录的 error 含同一文案 |

业务异常由服务层抛 `BizError(status_code, detail)`，全局处理器转成上述结构。没有独立的业务错误码，前端按 HTTP 状态码与 detail 文案处理。

`trace_id` 与响应头 `X-Request-Id` 是同一个值，也是服务端日志里 `[...]` 的那一段：拿它 grep 日志即可取到该次请求的全部记录。前端 axios 拦截器会把 5xx 的 `trace_id` 拼进错误提示，用户截图即可定位。

通过鉴权且未超限的请求，响应头带 `X-RateLimit-Limit` 与 `X-RateLimit-Remaining`（本自然分钟剩余次数），调用方可据此自适应；`/health` 与未鉴权的响应没有这两个头。

### 2.3 分页（FR-022）

除会话消息外，所有列表接口都是服务端分页，参数与响应结构统一：

```
GET /runs?page=1&page_size=20&status=failed&run_type=chat
```

| 参数 | 说明 |
|---|---|
| page | 从 1 起，默认 1 |
| page_size | 默认 20，上限 100，超出按 100 |
| 其余 | 各接口自己的筛选字段，全部在服务端生效 |

```json
{"items": [...], "total": 1234, "page": 1, "page_size": 20}
```

默认排序为 `id` 倒序（运行记录、审计、API Key、定时任务、会话按更新时间）或 `id` 正序（配置类），都带 `id` 作副键保证翻页稳定。空结果 `items` 为 `[]`。筛选参数全部在服务端生效，枚举型参数取值非法返回 422。

**排序参数**（页面深度优化，2026-09-06）：列表接口接 `sort`（字段名，各接口说明里列白名单）与 `order`（`asc` / `desc`，默认 `desc`）。`sort` 不在白名单 → 400 "不支持的排序字段：x，可选 …"；`order` 非法 → 422；`sort` 为空走默认排序。任何排序都自动追加 `id` 同向副键。

**时间区间参数**：按被过滤的列命名 `<列>_from` / `<列>_to`（运行记录 `started_from / started_to`，审计与文档 `created_from / created_to`），语义左闭右开 `[from, to)`，值为 ISO 8601 **必须带时区**（`2026-09-06T00:00:00+08:00`），不带时区 → 400 "…必须带时区"，`from >= to` → 400。

**批量接口**：`POST /<资源>/batch`，请求 `{"ids": [...], "action": "..."}`，`ids` 1～100 个（自动去重，空或超限 422），`action` 各资源白名单（非法 422）。语义是**逐条独立执行、逐条独立返回**，不是全成功或全失败：响应固定 200 `{"succeeded": [1, 2], "failed": [{"id": 3, "detail": "该模型已被 1 个智能体引用，无法删除"}]}`，单条的 404 / 409 / 400 都进 `failed`。各资源的 `action`：agents `publish / delete`；models、tools、api-keys、schedules、users `enable / disable / delete`；workflows、knowledge-bases、prompt-templates `delete`；documents `delete / reprocess`。

会话消息 `GET /conversations/{id}/messages` 是唯一例外：对话页需要整段历史，返回数组。前端下拉框取 `page_size=100` 的第一页（`OPTIONS_PAGE`），超过 100 项时要改为带 `q` 的服务端搜索，见演进路线。

### 2.4 ID 类型

主键以 JSON 数字传输。前端按 `number` 处理，比较用 `===`。平台内部 ID 远小于 2^53，暂不改为字符串；如引入雪花 ID 等长整型，必须全链路切换为字符串。

## 3. 认证与鉴权

### 3.1 JWT

`POST /auth/login` 返回的 token 有效期由 `ACCESS_TOKEN_EXPIRE_MINUTES` 决定（默认 1440 分钟）。payload：`sub` 用户 ID 字符串、`role`、`ver`（签发时的 `users.token_version`）、`exp`。每次请求都会查库确认用户存在且启用，停用立即生效：用户不存在或已停用 401「账号已停用或不存在，请重新登录」（2026-10-05 起，`15` OP-02；此前 403，前端不会清登录态）。前端在进入应用与页面切回前台时调 `GET /auth/me` 刷新角色、菜单与"必须改密"（最多一分钟一次）。

令牌吊销（2026-10-05 起，`15` OP-04）：`ver` 与库里的 `token_version` 不一致 → 401「登录已失效，请重新登录」。重置密码、停用、本人改密都会让版本 +1，之前签发的令牌全部作废（重新启用也不会复活停用前的会话）；此前要等到令牌自然过期。没有 `ver` 的令牌是这之前签发的，按 0 比对。

必须改密：`users.must_change_password` 为真的账号用 JWT 调 `/auth/me`、`PUT /auth/me/password` 以外的任何接口都 403「请先修改初始密码」（服务端强制，前端据此弹出不可关闭的改密框）。被管理员重置密码（默认勾选）或空库以内置默认口令初始化的 admin 会处于这个状态。

### 3.2 角色

| 依赖 | 允许 |
|---|---|
| `get_current_user` | 任何已登录用户 |
| `require_roles("admin")` | 管理员 |
| `require_roles("admin", "developer")` | 管理员与开发者 |

各接口的角色要求见第 4 节。

### 3.3 API Key 调用（FR-021）

- 请求头复用 `Authorization: Bearer ak_xxx`。`get_current_user` 按 `ak_` 前缀分流到 `api_key_service.authenticate`，判定顺序固定：① 查 `api_keys.key_hash = sha256(明文)` 且 `is_enabled`；② 归属用户存在且启用；③ 来源 IP 在 `allowed_ips` 白名单内（空名单不限制）；④ 限流：单 Key `rate_limit_per_minute`，为 0 时用全局 `RATE_LIMIT_API_KEY_PER_MINUTE`，按自然分钟固定窗口计数；⑤ 用带前置条件的 `UPDATE ... WHERE used < quota` 扣 1 次配额并更新 `last_used_at`。
- 通过后以 Key 归属用户的身份与角色执行，但只能调**作用域**内的资源（2026-10-05 起，`15` 3.7.1，D-09；此前等同于归属人登录，能调归属人能调的一切）：对话与 `/agents/available/{id}` 的智能体须在 `agent_ids` 内，否则 403 "该 API Key 无权调用此智能体"，`GET /agents/available` 只列作用域内的；工作流运行与续跑须在 `workflow_ids` 内，否则 403 "该 API Key 无权调用此工作流"，续跑另须是本 Key 发起的运行（否则 404 "运行记录不存在"）；对话检索只放行公开库，以及在 `kb_ids` 内且归属人当前角色可见的库——归属人是 admin 也不放行范围外的受限库（被挡的库检索步骤记 `kb_denied`）。作用域判定都在服务层，没有"作用域为空 = 全部放行"的分支。**每个通过鉴权的请求消耗 1 次配额**，与业务是否成功无关；被白名单拒绝或被限流的请求不扣配额。
- 错误：401 "API Key 无效或已停用"；403 "API Key 归属账号不可用"；403 "API Key 不允许从该 IP 调用"（同时写审计 `api_key_ip_rejected`，detail 含来源 IP 与 Key 前缀）；429 "请求过于频繁，请 N 秒后重试"（限流）；429 "API Key 配额已用尽"（不再累加 used）。
- 限流依赖 Redis：Redis 不可用时放行并记录故障，`/system/status.rate_limit.enabled=false` 且进 `degraded`；`RATE_LIMIT_ENABLED=false` 是配置关闭，不算降级。限流的 429 带 `Retry-After` 与 `X-RateLimit-*`，通过的请求带剩余额度，见 2.2。
- 可用范围：所有只要求登录的接口（`/auth/me`、`GET /agents/available`、`GET /agents/available/{id}`、`/agents/{id}/chat`、`/conversations*`），以及显式开放的 `POST /workflows/{id}/run` 与 `POST /workflows/{id}/runs/{run_id}/resume`。其余管理接口对 API Key 返回 403 "API Key 不能访问管理接口"。
- 开放新的执行类接口给 API Key：路由依赖改为 `require_roles(..., allow_api_key=True)`，并在本节登记。

### 3.4 分享访客令牌（2026-10-05 起，`15` 3.6，PB-01）

- 分享访客接口（4.19）不认平台 JWT 与 API Key，认**访客令牌**：`POST /public/shares/{code}/sessions` 签发，是与平台 JWT 共用 `SECRET_KEY` 的 JWT，`typ=share_guest`，带 `sid`（分享 id）、`vid`（访客 id）、`ver`（分享的 `token_version`）、`exp`；"仅登录"模式另带 `uid` 与 `uver`（签发时的 `users.token_version`）。请求头同样是 `Authorization: Bearer <访客令牌>`。
- 有效期：公开模式 30 天，剩余不足 7 天时任一访客接口（含 SSE）在响应头 `X-Share-Token` 下发新令牌（同一个访客 id），旧令牌到期前仍有效；"仅登录"模式同平台 JWT（`ACCESS_TOKEN_EXPIRE_MINUTES`）、不换发，过期后用平台 JWT 重新建会话（会话按 uid 归属，不丢）。
- 每次请求按顺序校验，任何一步不过 401「访问凭证已失效，请重新打开链接」：验签与过期 → `typ=share_guest` → `sid` 等于 URL 里链接码对应的分享（拿分享 A 的令牌调不了分享 B）→ `ver` 等于分享当前值（改访问密码、改访问方式、重置链接后旧令牌作废）→ "仅登录"模式按 `uid` 回库，须启用且 `token_version` 等于 `uver`（停用、重置密码、改密都吊销）。分享本身不可用时按 4.19 的 404 / 403。
- 平台接口（`get_current_user`）拒收带 `typ` 的令牌：访客令牌调 `/auth/me`、`/conversations` 等一律 401「Token 无效或已过期」。

## 4. 接口清单

角色列：`*` 任何登录用户，`A` 管理员，`AD` 管理员与开发者。

### 4.1 认证 `/auth`

| 方法 路径 | 角色 | 请求 | 响应 |
|---|---|---|---|
| POST /auth/login | 公开 | `{username, password}` | `{token, user: {id, username, role, is_active, must_change_password}}`；401 密码错、403 停用、429 锁定或来源 IP 每分钟超过 `RATE_LIMIT_IP_PER_MINUTE`；必须改密的账号照样能登录，拿到的令牌只能调下面两个接口；成功登录记 `last_login_at` |
| GET /auth/me | * | | `{id, username, role, is_active, must_change_password, public_base_url}`；必须改密的账号也能调。`public_base_url` 是配置的对外地址（`PUBLIC_BASE_URL`，末尾无斜杠），分享链接与 API 调用示例用；空串表示前端用浏览器当前访问的地址（2026-10-05 起，`15` PB-07；登录与改密响应里的 `user` 不带这一项） |
| PUT /auth/me/password | 登录用户（API Key 403） | `{old_password, new_password}`：新密码 6～128（422） | `{token, user}`：当前密码错 400「当前密码不正确」（连错 5 次锁 10 分钟，429）、新旧相同 400；成功后 `token_version` +1（本人其他设备上的会话与旧令牌全部失效）、清除必须改密，返回新令牌供当前页面继续用；写审计 `change_password`（不记密码）。2026-10-05 起（`15` OP-04；1C 的个人中心复用它） |

|---|---|---|---|

| DELETE /users/{id} | A | | `{code:0}`；409 仍持有模型/智能体/知识库/工作流；删除自己 → 400 |

### 4.4 智能体 `/agents`

### 4.8 知识库 `/knowledge-bases`

**可见性**（2026-10-05 起，`15` KB-01）：本节所有接口在角色校验之外，再按知识库的访问权限过滤——admin 看得到全部；其他角色只看得到公开库，或 `visible_roles` 含本角色的库。不可见的库对列表不出现，对详情、修改、改权限、变更记录、删除、文档（列表、上传、批量、续处理、重新解析、切片、删除）、检索一律 404「知识库不存在」，与真的不存在同一个响应（不暴露受限库是否存在）；批量删除知识库时进失败清单，文档批量对不可见的库整个请求 404。规则与检索闸门 `retriever.kb_allows` 同一口径（`06` 第 8 节）。此前这些接口只看角色，developer 能读、改、删仅 admin 可见的库。

```json
  "degraded": [{"item": "embedding", "message": "未配置 EMBEDDING_API_KEY…"}]
}
```

- `client_ip`（2026-10-05 起，`15` PB-07）：来源 IP 自检。`trusted_proxy` 即 `TRUSTED_PROXY_ENABLED`；`real_ip_header` 是本次请求有没有带合法的 `X-Real-IP`；`resolved` 是本次请求解析出的来源（上线后用它确认记的是真实公网 IP）。开关打开却没收到合法的 `X-Real-IP` 时 `ok=false` 并进 `degraded`（`item=client_ip`）——说明代理没有覆写来源，后端会退到客户端可伪造的 `X-Forwarded-For` 首项；开关关闭时不判定（本机开发经代理访问时来源恒为回环地址，属预期）。

- `embedding.mode`：`model` 用真实向量模型，`hash` 表示检索正在降级运行。
- `embedding.configured=false` 是配置性降级（没配 key），`configured=true` 且 `last_error` 非空是故障性降级。
- `login_guard.enabled=false` 表示 Redis 不可用、登录限流当前没有生效。
- `rate_limit.configured=false` 是配置关闭（`RATE_LIMIT_ENABLED=false`，不进 `degraded`）；`configured=true` 且 `enabled=false` 是 Redis 故障，进 `degraded`。
- `model_breakers` 只列非 closed 的模型：`open` 表示打开期内直接 503，`retry_after_seconds` 后自动放行一个探测；`half_open` 表示探测进行中。`open` 的模型进 `degraded`（`item=model_breaker`）。状态在进程内，多实例各自独立。
- `scheduler.registered_jobs` 小于 `enabled_jobs` 通常意味着有任务的 cron 表达式非法被跳过。
- `degraded` 为空即一切正常；前端只看这一项就能决定是否提示。

## 5. 对话 SSE 事件契约

响应头 `Content-Type: text/event-stream`，每个事件一行 `data: <JSON>` 加空行。事件顺序：`citations` → 若干 `delta` / `tool_call` / `tool_result` → `done`；任何阶段可能以 `error` 结束。装配页调试（4.5）：`prompt` → `citations` → 检索阶段的 `trace` → 若干 `delta` / `tool_call` / `tool_result` 与 `llm` / `tool` 类 `trace` 穿插 → `done`（调试版）。

| type | 字段 | 说明 |
|---|---|---|
| citations | `citations: [{kb_id, chunk_id, doc_name, content, score}]` | 首个事件；无知识库时为空数组 |
| delta | `content` | 回复文本增量 |
| tool_call | `id, name, arguments` | 模型决定调用工具；`arguments` 为解析后的对象，解析失败为 `{"_raw": 字符串}`（2026-09-29 前一轮里第二次起的工具调用参数会被拼到上一次后面，恒显示成 `_raw`；只影响显示，工具实际收到的参数正确） |
| tool_result | `tool_call_id, content` | 工具返回，截断 200 字符（调试 4000） |
| done | `message_id, run_id, conversation_id, usage: {prompt_tokens, completion_tokens, total_tokens}`，回放时另带 `replayed: true` | 正常结束。`usage` 是本轮各次模型调用之和（有工具调用时模型会被调多次；2026-09-29 前只剩最后一次的，运行记录的 token 与成本少算）。重复的 `client_message_id` 回放首次结果时（4.5），`message_id` / `run_id` / `usage` 都是首次的，不新增运行记录（2026-10-05 起） |
| prompt | `system_prompt, history_count` | **仅调试**，首个事件：实际发给模型的系统提示词（含注入的参考片段，截到 20000 字）与带入的历史条数 |
| trace | `step: {id, type, name, status, started_at, duration_ms, input, output, meta}` | **仅调试**，每完成一步推一条。`type`：`rewrite` 查询改写（开启时）；`retrieve` 每个（知识库, 查询）一条，`name` 知识库名，`input.query`，`output` 命中列表 `[{chunk_id, doc_id, doc_name, score, vector_score, keyword_score, rerank_score, location: {type, page / row / heading}}]`（不带正文，正文在 citations），`meta` 含 `candidate_count, returned, acl_rejected, kb_denied, rerank_mode, timings`，无权检索时 `status=denied`；`llm` 每次模型调用一条，`output: {content_chars, tool_calls}`，`meta: {model_id, first_token_ms, usage}`；`tool` 每次工具执行一条，`input` 入参、`output` 结果（≤ 4000 字），工具返回 `{"error": …}` 时 `status=error`。`TraceStep` 是全平台共用结构（`services/chat_trace.py`），线上调用链持久化（`15` OP-08）沿用 |
| done（调试） | `run_id, usage, metrics: {first_token_ms, latency_ms, retrieval_ms, cost, model_id, model_name, config_source}` | 调试不带 `conversation_id` 与 `message_id`；`cost` 读收尾后的运行记录 |
| error | `message` | 出错结束；此时运行记录已置 failed。业务错误原样下发（模型不可用、熔断中、"超过最大工具调用轮数（N），已停止"）；其余异常一律"生成失败，请稍后重试（trace: <X-Request-Id>）"，原文只在服务端日志与运行记录的 error 里（2026-09-25 起，此前下发异常原文） |

客户端主动断开（停止按钮）不会收到 `done`；服务端把已生成内容落库，运行记录置 `cancelled`。

**分享访客的事件**（`POST /public/shares/{code}/chat`，2026-10-05 起，`15` 3.6）：同样的事件序列，字段裁剪成访客口径——`citations` 每条只有 `{doc_name, content}`，`show_citations` 关闭时为空数组；`tool_call` 只有 `{id, name}`；`tool_result` 只有 `{tool_call_id}`；`done` 只有 `{message_id, conversation_id}`（没有 `run_id`、`usage`、`replayed`）；`error` 的文案按白名单：链接与额度类（链接不存在或已关闭、链接已过期、分享不可用、智能体已下线 / 未发布、今日额度已用完、你今天的提问次数已用完、请求过于频繁）、"消息不能为空"、"超过最大工具调用轮数"、"生成失败，请稍后重试（trace: …）"原样下发，其余（含熔断文案里的模型名、"模型不可用"）一律"服务暂时不可用，请稍后重试（trace: <X-Request-Id>）"，原文照常进日志与运行记录。公开模式令牌快到期时，响应头 `X-Share-Token` 带新令牌（3.4）。

前端解析器在 `frontend/src/api/chat.ts` 的 `streamSse`（`chatAgentStream`、`chatDebugStream`、`chatShareStream` 都是它的薄封装），新增事件类型时两端同批改。非 2xx 响应的错误文案与 axios 同一口径：422 取首条字段错误、5xx 拼追踪 ID、401 清登录态回登录页（2026-09-25 起；此前 422 显示成 `[object Object]`、401 只弹提示）；分享访客页注入访客令牌与自己的 401 处理（回到进入流程，不碰平台登录态），并读响应头 `X-Share-Token`（2026-10-05 起）。

## 6. 契约演进规则

- 改字段名、类型、枚举值：一次改到底，同批改路由、服务、前端 api 层与页面、本文档；不留 `新字段 || 旧字段` 兼容。
- 新增可选字段可以只加不删；删除字段先全仓搜索引用为零。
- 有第二个消费者（API Key 调用方）之后，破坏性变更要在本文档记录废弃时间。
- 改对话的 SSE 事件、请求体字段或错误码时，同批改智能体"发布渠道 → API 调用"卡片的对接说明（`frontend/src/components/publish/apiSnippets.ts`：端点、请求体、事件、错误码表与 curl / Python / JS 示例、"复制对接说明"的 Markdown）——对接方照着它写代码（2026-10-05 起，`15` PB-02）。
