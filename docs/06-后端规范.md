# 智枢·智能体平台 后端规范

版本 V2.2 · 2026-09-04 · 适用于 `backend/`

> 先读 `05-开发规范.md`，本文档只写后端特有的约定。

## 1. 分层与依赖方向

```
api/v1（接入层） → services（业务层） → core / db / rag / workflow / tools / model_gateway（能力层与数据层）
```

| 层 | 该做的 | 禁止 |
|---|---|---|
| `api/v1/*.py` | 定义请求模型、声明鉴权依赖、调用一个服务函数、返回结果 | 查库、写 if 业务判断、拼装复杂响应 |
| `services/*.py` | 业务规则、前置校验、事务提交、跨模块编排、写审计 | 依赖 `Request` / `HTTPException`、返回 FastAPI 对象 |
| `core/` | 安全、鉴权依赖、异常类型、审计写入、调度器 | 业务规则（调度器调用 `workflow_service` 是唯一例外） |
| `db/` | 引擎、会话、ORM 模型 | 业务判断 |
| `rag/ workflow/ tools/ model_gateway/` | 各自的能力实现，可直接用 `SessionLocal` 开自己的会话 | 调用 `services`、互相环形依赖 |

新模块按"路由文件 + 服务文件 + 必要时的能力模块"三件套创建，并在 `api/v1/router.py` 注册。

## 2. 路由写法

模板（照 `api/v1/agents.py`）：

```python
router = APIRouter(prefix="/things", tags=["things"])


class ThingIn(BaseModel):          # 只有本路由用的请求模型放这里；多路由共享的放 app/schemas
    name: str
    description: str = ""


@router.get("", response_model=Page[ThingOut])
def list_things(
    params: PageParams = Depends(page_params),
    q: str | None = Query(None, max_length=64, description="名称模糊匹配"),
    db: Session = Depends(get_db),
    user: User = Depends(require_roles("admin", "developer")),
):
    return thing_service.list_things(db, params, q)


@router.delete("/{thing_id}")
def delete_thing(thing_id: int, db: Session = Depends(get_db), user: User = Depends(require_roles("admin", "developer"))):
    thing_service.delete_thing(db, thing_id)
    return {"code": 0, "message": "ok"}
```

- 每个路由必须声明鉴权依赖；新增接口先回答"谁能调"，默认最小权限。
- 路径参数用 `xxx_id: int`。
- 请求模型字段给默认值时要与数据库默认一致。
- 响应：成功直接返回数据；删除返回 `{"code": 0, "message": "ok"}`；不新增 `code/message/data` 信封的接口。
- 异步路由只在需要 `await` 时用 `async def`（上传、模型测试、工作流）；同步 DB 操作的路由用普通 `def`，FastAPI 会放线程池。

## 3. 服务层写法

```python
def get_thing(db: Session, thing_id: int) -> Thing:
    t = db.get(Thing, thing_id)
    if t is None:
        raise BizError(404, "事物不存在")
    return t


def delete_thing(db: Session, thing_id: int) -> None:
    t = get_thing(db, thing_id)
    ref_count = db.query(Agent).filter(Agent.thing_id == thing_id).count()
    if ref_count:
        raise BizError(409, f"该事物已被 {ref_count} 个智能体引用，无法删除")
    db.delete(t)
    db.commit()
```

- 函数式模块，`db: Session` 永远是第一个参数；需要当前用户时传 `user: User`。
- 返回 ORM 对象（路由用 `response_model` 序列化）或 dict；同一模块内保持一种。
- 每个业务操作自己 `commit`；`create` 后 `refresh` 再返回，保证有 ID 与默认值。
- 被 `RESTRICT` 外键保护的删除，先查引用数给出可读的 409，不要让数据库报错冒到 500。
- 写审计用 `core.audit.record_audit(db, user, action, resource, resource_id, detail)`，在 commit 之后调用。
- 状态流转带前置条件：`if run.status != "awaiting_review": raise BizError(400, ...)`，不要先查后改不判断。

## 4. 数据访问

- 列表查询一律 `core.pagination.paginate(query, params, serialize)`：路由用 `Depends(page_params)` 取分页参数，query 必须带确定排序并含 `id` 副键；筛选条件全部下推到 query，枚举型筛选在路由用 `Literal` 声明让非法值返回 422。
- 禁止 N+1：先批量取主数据，收集关联 ID，一次 `in_()` 取关联，内存装配。`run_service._cost_by_run` 是范例：一页记录只查两次。
- 会话生命周期：路由用 `Depends(get_db)`；后台任务、调度线程、能力层自己 `SessionLocal()` 并在 `finally` 关闭；不要跨线程共用同一个 Session 做并发操作。
- 跨线程执行（`asyncio.to_thread`）时，主协程在等待期间不得再碰传入的 Session。
- JSON 列改动要整体赋值（`run.output = {...}`），原地修改 dict 不会被 SQLAlchemy 发现。
- 会话摘要边界：`conversations.summary_upto_message_id` 指向摘要已覆盖的最后一条消息。当前没有删除单条消息的接口；将来新增删除消息或"重新生成"删旧回复的接口时，必须同批处理边界越界（被删消息 id ≥ 边界时把边界回退或清空摘要），否则摘要会引用已不存在的内容。

## 5. 运行记录

所有执行入口的固定写法：

```python
run = run_service.create_run(db, "workflow", user.id, workflow_id=wf.id, input_data={"input": text})
...
run_service.finalize_run(db, run, "success", output={...})        # 或 "failed", error=str(e)
```

- 终态只有 `success / failed / cancelled`；`awaiting_review` 由 `workflow_service.execute_workflow` 单独处理，不写 `finished_at`。
- `finalize_run` 幂等，已终态的记录不会被覆盖；不要自己写 `run.status = ...`。
- 长任务在 `finally` 里兜底收尾（对话流的客户端中断就是这样处理的）。

## 6. 工作流节点开发

新增一种节点的完整步骤：

1. `workflow/engine.py`：写 `_make_xxx_node(config, run_id, node_id) -> Callable`，内部结构固定：`_get_node_input` 取输入 → `_start_node` 写日志 → 执行 → `_finalize_node_output` 写 `output / node_outputs` → `_finish_node(success)`；异常 `_finish_node(failed)` 后 **重新抛出**，让运行记录失败。
2. 注册到 `NODE_BUILDERS`；需要角色的节点参照 `kb_retrieval` 在 `build_workflow` 里特殊处理。
3. 前端 `pages/WorkflowEditor.tsx`：`PALETTE` 加节点、`buildDetail` 加摘要、`saveNode` 加配置字段、配置表单加控件、`onNodeClick` 的初始值补字段。
4. 文档：`02-架构设计.md` 节点表、`03-数据库设计.md` 的 graph 示例（如有新配置）。
5. 测试：`tests/` 里用一个最小图跑通成功与失败两条路径。

约束：节点函数是同步的；需要调用异步工具用 `asyncio.run`（节点运行在线程池或调度线程，没有运行中的事件循环）；节点内的 DB 访问自己开 `SessionLocal`。

## 7. 工具开发

- 内置工具：`tools/executor._execute_builtin` 里按名字分发，同时在 `tools/langchain_tools.py` 用 `@tool` 提供给智能体，两处都要加。工具函数的 docstring 就是给模型看的描述，写清参数含义。
- HTTP 工具：不改代码，在工具管理里配置 `config.url / method / headers`。
- 调用无参工具时必须传空对象 `{}`，否则 binding 报错；代码里不要定义与 `tools` 同名的局部变量。
- 工具返回值必须是可 JSON 序列化的 dict，失败返回 `{"error": ...}` 而不是抛异常。

## 8. RAG 扩展点

| 要改什么 | 改哪里 |
|---|---|
| 新文件类型 | `rag/parser.parse_document` 分发 + 新解析函数；`rag/pipeline.chunk_segments` 加分片策略；`meta` 写清来源定位字段 |
| 向量模型 | 只改配置 `EMBEDDING_*`；维度变了要走迁移改列并重新处理文档 |
| 召回策略 | `rag/retriever._collect_candidates`；保持返回结构不变 |
| 重排 | `rag/rerank.rerank` 接口固定 `(query, candidates, keywords) -> ranked`，可换成模型打分 |
| 权限 | `_acl_condition` 与 `_authorize` 必须同步改，两道闸门语义一致 |

`embed_texts / embed_query` 失败会退化为 hash 向量，改动时必须保留这条退路。降级必须可见（见第 13 节）：

- 入库走 `embed_texts_detailed`，返回的 `mode / model / dim` 写进切片 `meta`，事后能区分哪些切片是降级入库的。
- 每次降级打 WARN，并由 `embedding_status()` 汇报当前模式与最近一次失败，接进 `/system/status` 与 `/health`。
- 未配 `EMBEDDING_API_KEY` 属配置性降级（`configured=false`），配了但调用失败属故障性降级（`last_error` 非空），两者要分开报。

## 9. 配置

- 新增配置项：`config.Settings` 加字段并给默认值 → `backend/.env.example` → 根目录 `.env.example`（compose 需要时）→ `docker-compose.yml` 透传 → `08-运行与部署.md` 环境变量表。五处缺一不可。
- 代码里只通过 `from app.config import settings` 读配置，不直接 `os.environ`。
- 环境相关的一切（地址、密钥、超时、开关、维度）走配置，不硬编码。

## 10. 安全

- 密码 `hash_password / verify_password`；模型密钥 `encrypt_secret / decrypt_secret`；API Key 只存 `sha256`。
- 接口输出模型对象时用 `ModelOut` 这类不含密钥的响应模型。
- 日志与异常信息不打印密钥、密码、token、完整请求头。
- 表达式求值只允许 `_eval_condition` 那种受限命名空间；不要新增 `eval / exec` 调用点。
- CORS 目前是通配放开，对外部署前收成域名白名单。

## 11. 迁移脚本

文件名 `YYYYMMDD_HHMMSS_<随机 6 位>_<描述>.py`，放 `scripts/migrations/`。头部 docstring 固定写：改什么、为什么、影响、执行后必做、幂等说明、执行命令。

```python
"""迁移：xxx 表增加 yyy 列。

改什么：...
为什么：...
影响：...
执行后必做：...
幂等：ADD COLUMN IF NOT EXISTS，重复执行无副作用。
执行：cd backend && .venv/bin/python scripts/migrations/<本文件>.py [--apply]
"""
```

- DDL 用 `IF NOT EXISTS / IF EXISTS`；数据修复用带条件的 `UPDATE`。
- 有删除或批量更新的脚本默认只预览行数，加 `--apply` 才执行。
- 先在本地或测试库跑通，再在共享库执行（执行前遵守铁律 7）。

## 13. 日志与错误可见性

平台有多条"失败了也能继续跑"的降级路径（向量模型退 hash、Redis 挂了限流失效、摘要失败退截断）。
它们不报错、不影响响应，只让效果变差 —— **静默降级是本项目最贵的缺陷类型**，必须靠日志与状态接口兜住。

### 13.1 追踪 ID

- 每个请求由 `core/middleware.RequestContextMiddleware` 分配 `X-Request-Id`，写入 contextvar 与 ASGI scope。
- 日志格式固定 `时间 级别 [request_id] logger: 消息`；无请求上下文（启动、调度线程、线程池）时为 `-`。
- 错误响应体带 `trace_id`，与响应头同值。排查线上问题的标准动作：拿用户给的 trace_id `grep` 日志。
- **contextvar 不跨线程传播**：`asyncio.to_thread` 与线程池里的日志会显示 `-`，需要关联时把 run_id 打进消息里。

### 13.2 异常捕获规则

| 情况 | 写法 |
|---|---|
| 能明确预期的异常 | 捕获**具体类型**（`json.JSONDecodeError`、`redis.RedisError`、`httpx.HTTPError`、`JWTError`），不用 `except Exception` |
| 预期内、可继续的失败 | `logger.warning` 写清降级成什么、影响是什么 |
| 意外故障 | `logger.exception` 留完整堆栈，再处理或重抛 |
| 控制流异常 | 单独捕获（`GraphInterrupt` 必须先于 `Exception` 捕获，否则暂停会被误判成失败） |

- **禁止空 `catch`、禁止捕获后不留痕**。`except Exception` 只允许出现在"兜底且必须留堆栈"的位置。
- 业务失败（`BizError`）记 INFO 不记堆栈；只有故障才配 ERROR，否则告警会被淹没。
- 日志不打密钥、token、密码、完整请求头；JWT 校验失败只记异常类型与原因。
- 循环内不逐条打日志，批量操作打汇总。

### 13.3 新增降级路径的三件事

1. 失败时 `logger.warning`，写明降级成了什么。
2. 把状态暴露到 `rag/embeddings.embedding_status()` 那样的查询函数里，并接进 `services/system_service.get_system_status`。
3. 如果影响数据质量，把降级信息写进数据本身（切片 `meta.embedding_mode` 就是这么做的），事后才能区分哪些数据需要重建。

入口限流（`core/rate_limiter.status()`）与模型熔断（`model_gateway/breaker.status()`）都按这三件事接入；新增外部依赖的保护开关时照此办理。模型调用一律走 `gateway.guarded_*` 包装，不要绕过熔断直接 `llm.invoke`。
