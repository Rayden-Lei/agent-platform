## 一、架构

```
Mac (192.168.121.140)
  ├─ backend uvicorn :8000   ← 跑在 Mac，ENV_FILE=.env.local
  ├─ frontend Vite  :5173    ← /api/ 反代到 127.0.0.1:8000
  └─ SSH 隧道（launchd 常驻）  ← 本机连云端依赖的唯一通道
        ↓
云服务器 47.118.52.252
  ├─ PostgreSQL 16 + pgvector  :5432
  ├─ Redis 7                   :6379
  └─ MinIO                     :9000
```

**依赖服务只监听云端的 127.0.0.1，不对公网开库。** 本机经 SSH 隧道访问：

| 本机端口 | → 云端 | 用途 |
|---|---|---|
| 15432 | 5432 | PostgreSQL |
| 16379 | 6379 | Redis |
| 19000 | 9000 | MinIO |

隧道由 launchd 常驻，开机自启、断了自动重连：

```bash
# 状态
launchctl list | grep agent-platform-tunnel
# 重启
launchctl kickstart -k gui/$(id -u)/com.lei.agent-platform-tunnel
# 配置文件
~/Library/LaunchAgents/com.lei.agent-platform-tunnel.plist
```

## 三、启动与停止

```bash
./scripts/dev.sh           # 前后端（dev 模式，改代码热更新）
./scripts/dev.sh backend   # 只起后端
./scripts/dev.sh frontend  # 只起前端
./scripts/dev.sh stop      # 全停
./scripts/dev.sh status    # 看状态 + 云端地址
```

日志：`agent-platform/logs/{backend,frontend}.log`（已进 .gitignore）。

脚本启动前会先探隧道端口（15432/16379/19000），未就绪直接打印恢复命令——
依赖全在云端后，`connection refused` 的第一嫌疑是隧道断了，不是代码问题。

### 外网访问

**本地不再用 cloudflared 临时隧道**（2026-11-06 移除，`scripts/share.sh` 一并删掉）。
需要外网看就直接看云服务器，push 后 30 秒自动部署：

| 用途 | 地址 |
|---|---|
| 生产（nginx + dist） | http://47.118.52.252:19080 |
| 开发（vite dev + HMR） | http://47.118.52.252:19173 |

本机 `localhost:5173` 只用于本地调试，不对外。

### 代理坑（排查网络时先看这条）

本机开着 Clash（`127.0.0.1:7890`，macOS 系统代理已开）。**CLI 工具不读系统代理**：

- `curl` 访问需要代理的地址要显式带 `-x http://127.0.0.1:7890`，否则超时返回 000
- 浏览器走系统代理，所以"网页打开正常、命令行超时"是正常现象，别误判成对方服务挂了
- 云服务器到 GitHub 的 443 不稳定，代码同步走 SSH(22) 协议（见云服务器部署存档）
