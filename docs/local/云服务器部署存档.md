## 四、自动部署

本地 push 后，服务器 **30 秒内**自动拉取并更新。

```
本地 push → GitHub → (SSH 22) → ap-deploy.timer 每 30 秒 fetch
                                    ↓ 有变化
                              git reset --hard
                                    ↓
              ┌─────────────────────┴─────────────────────┐
        后端 uvicorn --reload                    前端
        监听 backend/app/                   ├─ vite dev：HMR 自动生效
        改 .py 即重启                        └─ dist：重新 npm run build
```

- 脚本：`/usr/local/bin/ap-deploy`
- 定时器：`ap-deploy.timer`（OnUnitActiveSec=30s）
- 日志：`/var/log/ap-deploy.log`
- 只在 `frontend/` 有变更时重建 dist；只在 `requirements.txt` / `package.json` 变更时装依赖
- **变更文件列表必须在 `git reset` 之前取**：reset 之后 HEAD 已是新版本，
  `$BEFORE..$AFTER` 的 diff 变空，重建分支永远不会触发（2026-11-05 踩过）

`ap-webhook`（`127.0.0.1:9001`）也部署了但没启用——它需要从公网暴露端口才能收 GitHub 的推送。
30 秒轮询够用，就没开。要用的话：安全组开一个 19xxx 端口、监听改 0.0.0.0、GitHub 仓库配 webhook
（密钥在 `/root/.ap-webhook-secret`）。

## 六、数据库

PostgreSQL 16 + pgvector，库名 `agent_platform`，用户 `admin`。
密码存在 `/root/.ap-dbpass`（chmod 600），`backend/.env` 里引用。

内存参数（1.7 G 机器，2026-11-05 调过）：

```
shared_buffers        = 384MB
effective_cache_size  = 512MB
work_mem              = 8MB
maintenance_work_mem  = 64MB
max_connections       = 40
```

数据是 2026-11-05 从 Windows 那套（192.168.121.85:5433）用 `pg_dump -Fc` 导出、
`pg_restore` 导入的。**导入前必须先 `CREATE EXTENSION vector`**，否则
`document_chunks.embedding` 列建不出来，恢复会报 11 个错。

## 九、踩过的坑

**1. curl 访问需代理的地址要显式带 `-x`。** 本机开着 Clash（127.0.0.1:7890），但 CLI 工具不读
macOS 系统代理设置。不带 `-x` 会超时返回 000，容易被误判成对方服务挂了。浏览器走系统代理，
所以"网页正常、命令行超时"是正常现象。

**2. 服务器到 GitHub 443 不稳。** 用 SSH(22) 协议 + Deploy Key。

**3. 内存小，构建要设堆上限。** `NODE_OPTIONS=--max-old-space-size=1024`，
否则 vite build 会把 1.7 G 吃穿。实测构建 36 秒，峰值靠 swap 兜住。

**4. 导入数据库前先建 vector 扩展**（见第六节）。

> 历史记录：2026-11-06 之前本地用 cloudflared 临时隧道做外网访问，踩过"隧道不能走 HTTP 代理"
> 的坑（QUIC/UDP 被 TCP 代理掐断）。现在本地不再起隧道，外网直接访问云服务器，
> 那套代码和 `scripts/share.sh` 已一并删除。

## 十一、沙箱在线上是 bwrap 模式（2026-11-06 实测）

`GET /system/status` 的 `sandbox` 字段：

```
{'mode': 'bwrap', 'degraded': False, 'reason': None, 'detail': {'bwrap': '/usr/bin/bwrap'}}
```

**未降级。** 前提是装了 bubblewrap 并加载 AppArmor profile（`docs/08` §7.5 有完整步骤）：

```bash
apt install bubblewrap
# /etc/apparmor.d/bwrap 已写入并 apparmor_parser -r 加载
```

线上实测（`agent-platform-backend` 服务进程内）：

| 测什么 | 结果 |
|---|---|
| 环境变量 | 只剩 `LANG` / `PATH` / `PWD` / `PYTHONDONTWRITEBYTECODE` / `PYTHONIOENCODING`；`DATABASE_URL` / `AES_KEY` 均为 null |
| 网络 | 连后端自己(8000)、postgres(5432)、外网(1.1.1.1:80) 全部 blocked |
| 宿主文件 | `/home`、`/etc/shadow` 在沙箱内不存在 |
| 超时 | 2 秒墙钟，`timed_out=true` |
| 内存上限 | 128MB 上限下申请 500MB → `MemoryError` |
| 工作流代码节点 | 运行输出 `steps: ["code:bwrap", "code:bwrap"]`，节点里读 `AES_KEY` 得 null、读 `/root` 得 false |

**注意**：`agent-platform-backend` 现在以 **root** 跑，而 AppArmor 对 root 不生效 ——
所以 root 下能跑不代表将来换成非 root 账号也能跑。换账号前用那个账号重新验证一次。
