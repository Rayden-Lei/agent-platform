## 三、下一步：P2 技能（Skills）

目标：给智能体挂「操作手册」。默认**渐进式披露**——只把 name + description 放进提示词，模型需要时调内置工具 load_skill(name) 取正文；短小且每轮都要的技能可以开 always_on 全文注入。

### 1. 数据层
- 新表 skills：id / name(unique, 英文短横线) / display_name / description / content / resources(jsonb) / always_on(bool, 默认 false) / is_enabled(bool, 默认 true) / version(int, 默认 1) / created_by / created_at / updated_at。
  - 首版**只存文本**，resources 留空数组；正文上限建议 **64KB**（超了 400，别让一条技能把上下文吃光）。
  - content 变化时 version + 1（与提示词模板同一口径）。
- agents 加 skill_ids jsonb（与 kb_ids / tool_ids 同风格；没有外键，与现状同级）。
- **一次性迁移**：agent_versions.snapshot 里补 skill_ids: []。快照字段清单只有 runtime/agent_config.py 的 SNAPSHOT_FIELDS / snapshot_of / normalize_snapshot 一处定义——改那里，发布、回滚、恢复、差异比较自动跟上。
  - 读取存量快照时**不留 snap.get('skill_ids', []) 运行时兜底**（规范：契约一次切换），靠迁移脚本补齐。

### 2. 后端
- 新 service app/services/skill_service.py：增删改查 + 分页（与 prompt_template_service 同写法，先读它）。
- 路由 app/api/v1/skills.py：GET / POST / PUT / DELETE，admin/developer；写审计（正文是可能含内部信息的资产，与提示词模板同口径）。
- **内置工具 load_skill(name)**：加进 app/tools/builtin.py 的声明 + app/tools/langchain_tools.py 的执行分支。
  - **必须白名单**：只允许读本次装配的 skill_ids 里的技能，传别的返回「技能不存在」——否则模型能读任意技能（越权）。
  - 白名单要能从工具执行处拿到：现有 build_tools(tool_dbs, source, agent_id, run_id) 已经带上下文，按同样的方式把 skill 白名单传进去。
- 装配：chat_service._context_from_config 里按 cfg.skill_ids 拼两段进系统提示——「可用技能」目录（name: description，一行一个）+ 每个 always_on 的正文。
  - AgentRunConfig 要加 skill_ids 字段（run_config_from_snapshot 里填）。
- 分享访客：**不返回技能正文**（与提示词同口径）；访客对话是否装配技能按分享配置，首版跟 allow_http_tools 一致处理即可。

### 3. 前端
- /skills 页：列表（名称、显示名、是否常驻、版本、更新时间）+ 编辑弹窗（display_name / name / description / Markdown 正文 / always_on 开关）。
- 装配页加「技能」区块（多选，说明「技能只在需要时加载，不占常驻上下文」）；**与「提示词」区块分开**，别让人分不清模板和技能。
- nav.tsx 的能力组加「技能」一项（与现有图标风格一致）。
- 注意：visibleNavItems 已按 roles 过滤，新增项记得写 roles: ['admin', 'developer']。

### 4. 用例（负向优先）
- load_skill 传未绑定的技能名 → 「技能不存在」；传已停用的 → 同样拒绝。
- 保存时正文超 64KB / name 撞名 / name 格式非法 → 400。
- 快照含 skill_ids：发布后改绑定不改线上（发布语义）；回滚恢复旧快照时 skill_ids 一并还原。
- always_on 的技能正文进系统提示；非 always_on 只进目录（断言系统提示里没有正文）。
