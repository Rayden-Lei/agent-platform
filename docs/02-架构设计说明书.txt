========================================
智能体中台 架构设计说明书 (ADD)
版本 V1.0
========================================

一、设计目标与原则
目标：在满足几十并发、私有化部署、技术/算法团队自用的前提下，做到简单、可维护、可扩展，避免过度设计。
原则：
1. 单体优先：主服务单体部署，内部模块化拆分，需要时再拆微服务。
2. 插件化扩展：模型、工具、工作流节点用统一接口，新增不改核心。
3. 数据库为唯一配置源：智能体、工作流等配置全部落库（符合需求）。
4. 异步解耦：耗时任务（文档解析、向量化、工作流执行）走后台队列异步处理。
5. 安全内建：密钥加密、密码哈希、JWT 鉴权贯穿始终。

二、总体架构（分层）
第一层 接入层：Web 控制台（React）、REST API、SSE 流式通道。
第二层 应用层：认证、模型管理、智能体、对话、工具、知识库、工作流、监控八大业务模块。
第三层 能力层：模型网关、RAG 管道、工具执行器、工作流引擎、会话管理器。
第四层 数据层：PostgreSQL（含 pgvector）、Redis、MinIO。
第五层 基础设施：Docker Compose 私有化部署。

三、核心组件说明
1. 模型网关 Model Gateway：统一封装各厂商接口，负责请求适配、流式转发、重试、超时、密钥解密。插件式 Provider 接口，新增厂商只需加一个适配器。
2. 工作流引擎 Workflow Engine：解析 DAG 图，按拓扑顺序执行节点，支持条件分支、循环、并行，节点级日志与状态持久化。
3. RAG 管道 RAG Pipeline：文档解析、切片、向量化、检索、重排、引用回填六步，异步任务驱动。
4. 工具执行器 Tool Executor：内置工具 + HTTP 工具，统一 JSON Schema 校验参数，安全超时控制。
5. 会话管理器 Session Manager：管理多轮对话上下文、消息持久化、token 预算截断。

四、核心流程设计
4.1 对话流程：
用户消息 -> 鉴权 -> 加载智能体配置 -> 组装会话上下文 -> 判断是否 RAG（检索知识库）-> 组装提示词 -> 模型网关流式调用 -> 判断工具调用（循环执行）-> 流式返回 -> 落库消息与用量。

4.2 RAG 流程：
上传文档 -> 存 MinIO -> 异步解析 -> 切片 -> 向量化 -> 写 pgvector -> 检索（向量 + 关键词混合）-> 重排 -> 回填引用。

4.3 工作流执行流程：
触发运行 -> 创建 run 记录 -> 解析 DAG -> 拓扑排序 -> 逐节点执行（节点级状态落库）-> 条件分支判断 -> 循环控制 -> 汇总输出 -> 标记完成/失败。

五、关键设计决策
决策1 单体 vs 微服务：选单体 + 内部模块化。几十并发下微服务纯增复杂度；模块边界清晰，未来可独立拆分。
决策2 模型网关自研 vs LiteLLM：自研轻量网关。需求是屏蔽差异 + 流式 + 密钥管理，自研可控性更好，借鉴 LiteLLM 适配思路。
决策3 工作流引擎自研 vs LangGraph：自研轻量 DAG 引擎。可视化编排需要自己的节点模型与前端联动，自研保证图结构、节点日志、循环控制完全可控；智能体节点内部复用对话能力。
决策4 向量库：pgvector。复用现成 PostgreSQL，减少一个组件，几十万级向量完全够用。
决策5 任务队列：MVP 用 FastAPI 后台任务，量上来再升级 Redis + Celery/RQ。文档解析、向量化、工作流执行均异步。
决策6 流式输出：SSE（Server-Sent Events）。简单可靠，私有化内网无代理问题，比 WebSocket 更轻。

六、部署架构
单机 Docker Compose：
容器1 后端 API（FastAPI + Uvicorn）
容器2 前端（React 静态资源 + Nginx 反向代理）
容器3 PostgreSQL + pgvector 扩展
容器4 Redis
容器5 MinIO
Nginx 统一入口，HTTPS 可选。PG/Redis/MinIO 均挂数据卷持久化。

七、后端目录结构规划
app/
  main.py           应用入口
  config.py         配置
  db/               数据库连接与 ORM 模型
  api/              路由（auth/models/agents/chat/tools/kb/workflows/runs）
  services/         业务逻辑层
  core/             安全、依赖注入、异常处理
  model_gateway/    模型网关与各 Provider 适配器
  rag/              RAG 管道
  workflow/         工作流引擎与节点实现
  tools/            工具执行器
  tasks/            后台异步任务

八、前端目录结构规划
src/
  pages/            页面（登录/模型/智能体/知识库/工作流/工具/监控）
  components/       通用组件
  workflow/         React Flow 编排画布与节点面板
  api/              接口封装
  store/            状态管理

九、风险与应对
1. 工作流引擎复杂度高：MVP 先支持 6 类节点（开始/结束/智能体/工具/条件/循环），循环设最大迭代上限防死循环。
2. 文档解析格式多：先支持 PDF/Word/Markdown/TXT，逐格式加解析器。
3. 流式与工具调用并发：用 asyncio 异步处理，避免阻塞。
4. 模型接口差异：网关统一抽象，新模型按适配器扩展。
