# 智枢·智能体平台 前端规范

版本 V2.2 · 2026-09-04 · 适用于 `frontend/`

> 先读 `05-开发规范.md`，本文档只写前端特有的约定。技术栈：React 18 + TypeScript + Vite 5 + Ant Design 5 + React Router 6 + zustand + axios + @xyflow/react。

## 1. 页面骨架与滚动（最高频错误，先看）

**滚动条只能出现在中间内容区；顶部操作区与底部分页钉死；整页一起滚 = 错。**

外层容器由 `AppLayout` 提供：`Content` 已是 `flex: 1; min-height: 0; display: flex; flex-direction: column`，内容区外还包了一层 `overflow: hidden`。页面根元素只需要接上这条链：

```tsx
const { tableProps, reload } = usePagedList(listThings)   // 服务端分页 + 竞态保护，见第 7 节

<div style={{ flex: 1, minHeight: 0, display: 'flex', flexDirection: 'column', gap: 16 }}>
  <div style={{ display: 'flex', justifyContent: 'space-between', flexShrink: 0 }}>
    <h2>页面标题</h2>
    <Button type="primary">操作</Button>
  </div>
  <div className="fixed-table-wrapper">
    <Table rowKey="id" {...tableProps} columns={columns} scroll={{ x: 'max-content' }} />
  </div>
</div>
```

- 根元素 `flex: 1; minHeight: 0`；**`minHeight: 0` 必写**，否则 flex 子项不肯收缩，滚动条会跑到外层。
- 顶部区 `flexShrink: 0`。
- 列表页表格必须包在 `fixed-table-wrapper` 里，由它让表体内部滚动、分页固定底部（样式在 `styles.css`）。
- 禁止 `height: calc(100vh - ...)` 这类写死高度；禁止在页面根元素上写 `overflow: auto` 让整页滚（只有工作台这种纯卡片页例外）。
- 对话页：会话列表与消息区各自滚，输入框钉死；编辑器页：画布区 `flex: 1; minHeight: 0`，左右面板各自 `overflow: auto`。
- 弹窗与抽屉同理：头尾钉死，内容区滚。

## 2. 目录与分层

| 位置 | 放什么 | 不放什么 |
|---|---|---|
| `api/client.ts` | axios 实例与拦截器 | 业务接口函数 |
| `api/<域>.ts` | 按领域拆分的接口具名函数与返回类型（`core` 分页 / 批量契约，`agents`、`runs`、`stats`、`chat` 含 SSE 解析器…）；`api/index.ts` 只做 re-export，页面仍从 `'../api'` 导入（2026-09-06 修订：单文件超 300 行后拆分） | 组件逻辑 |
| `constants/` | 全站字典：`status.ts` 状态文案与语义色、`resources.tsx` 资源注册表（关联跳转）、`nav.tsx` 导航与角色可见性 | 页面私有映射 |
| `utils/` | 纯函数：`time`（dayjs 格式化 / 区间）、`format`（数字 / 成本 / 百分比）、`errors`（`errorText`）、`csv`、`diff` | 依赖 React 或请求 |
| `store/` | 跨路由的领域状态（当前用户、token、系统状态轮询、未保存标记） | 某个页面的临时表单值 |
| `hooks/` | 可复用的状态逻辑（`usePagedList`、`useAsyncData`、`useQueryState`、`useOpenParam`、`useBatchAction`、`useSystemStatus`） | 组件与请求封装 |
| `components/common/` | 通用展示件：`StatusTag`、`TimeCell`、`ResourceLink`、`JsonView`、`TokenUsage`、`EnableSwitch`、`SearchInput`、`DateRangeFilter`、`ErrorState`、`EmptyState`、`BatchActionBar`、`BatchResultModal`、`DiffView` | 发请求 |
| `components/layout/` | 页面骨架：`ListPage`、`DetailPage`、`PageHeader`、`FilterBar`、`StatCards`、`DegradedBanner`、`SideNav` | 业务逻辑 |
| `components/charts/` | 图表封装（`@ant-design/plots` 懒加载）：`ChartCard`、`TrendLine`、`StackedBar`、`Donut`、`Sparkline`、`theme` | 页面里直接 import `@ant-design/plots` |
| `components/<域>/` | 某个领域页面的子组件（`chat/`、`prompt/`、`tools/`、`runs/`…）与共享类型 | 发请求 |
| `pages/` | 一路由一文件，负责取数、状态与编排；详情页 `XxxDetail.tsx` | 直接 `axios / fetch` |
| `styles.css` | 全局样式与可复用类 | 页面私有样式（页面私有的用内联 style） |

## 3. 请求层

- 组件只 `import { listAgents } from '../api'`，不关心 URL、请求头、token。
- 新接口先在 `src/api/` 目录按 URL 搜一遍，命中就复用；一个接口只封装一次，放进对应领域文件。
- 函数命名 `listXxx / createXxx / updateXxx / deleteXxx / <动作>Xxx`，参数只传意图相关字段。
- 拦截器已把响应解包成 `res.data`；列表函数返回 `Page<T>`（`{items, total, page, page_size}`），`api/core.ts` 的 `get / post / put / del<T>()` 已收窄类型，页面不要再 `as any`。
- 错误提示统一用 `errorText(e, '操作失败')`（`utils/errors.ts`）：字符串 detail 直接用，422 数组取首条 msg；批量操作用 `BatchResultModal` 说明失败了哪几条。
  5xx 的追踪 ID 已由 `client.ts` 拦截器拼进 `detail`（形如"服务器内部错误…（trace: 1de7aa…）"），页面不用自己拼。
- 依赖状态用 `useSystemStatus()`（共享 store，多个订阅者共用一个定时器，页面不可见时暂停）：`degraded` 非空由 `DegradedBanner` 在顶栏下统一提示；页面只在需要局部信息时读 `status.embedding / model_breakers / scheduler`，不要各页面自己判断、也不要再直接调 `getSystemStatus()`。
- 对话流式走 `chatAgentStream`（fetch + ReadableStream），因为 axios 不支持浏览器端流式读取。新增 SSE 事件类型在这里加分支，同批改后端与 `04-接口设计.md`。
- **竞态**：快速切换会话或筛选时先发的请求可能后到。列表页交给 `usePagedList` 的请求序号处理；详情页、抽屉、统计卡用 `useAsyncData`（同样带请求序号）；对话页用 `AbortController`；不能裸 `await` 后直接 set。
- 轮询与定时器在组件卸载时清理。文档处理状态：**只在有处理中（uploading / parsing / chunking）的文档时每 3 秒轮询，没有处理中的即停，页面不可见时暂停**（2026-09-06 修订，取代"上传后延迟刷新"）；运行详情在非终态时同样有界轮询。
- 关联跳转一律用 `<ResourceLink type id name />`（`constants/resources.tsx` 是唯一映射）：详情页型资源跳 `/xxx/:id`，抽屉型资源跳列表页 `?open=:id`（列表页用 `useOpenParam` 响应）。抽屉里出现的关联也跳页面，**不在抽屉上再叠抽屉**；抽屉里要编辑就用弹窗（模板页 2026-09-06 改法）。
- 计数列跳到"按它筛选的列表"（如模型的智能体数跳 `/agents?model_id=`）时，目标列表必须把该参数放进 `useQueryState` 的默认值里真正下推到服务端，并在筛选条显示为可关闭的标签（`AgentFilters` / `RunFilters` 的写法）；只放在 URL 里不生效的链接等于骗人。
- 开发与 preview 的反代键是正则 `^/api/`，不能写成前缀 `/api`：前端路由 `/api-keys` 会被吃掉（见 `08` 2.2）。新增以 `api` 开头的路由前先想到这条。

## 4. 三态：加载 / 空 / 错误

- 异步区域必须处理三种状态且互斥：`loading` 时不显示"暂无数据"。
- 表格用 `usePagedList` 的 `emptyText` 选项（加载中留白、失败显示错误、否则显示空态）；卡片 / 详情用 `useAsyncData` 的三态配 `ErrorState`（带重试）与 `EmptyState`（带下一步动作）；空态要说明下一步能做什么（"从节点库拖入节点开始编排"）。
- 切换会话或页签时先清空旧数据再加载，避免新页签露出上一屏内容。
- 请求失败必须有可见反馈，禁止 `catch {}` 静默。

## 5. 状态管理

- 全局 store 只有 `useAuth`（token、user、setAuth、logout），持久化在 localStorage。
- 页面内状态用 `useState`；父子共享用 props；跨路由共享才进 store。
- 派生数据用计算，不维护第二份副本；流式追加消息时按 `Chat.tsx` 的 `patchLast` 做不可变更新，不原地改数组。
- 服务端数据与编辑态分离：编辑弹窗用 `form.setFieldsValue(record)` 拷贝，不直接改列表里的对象。

## 6. 视觉与品牌

- 主色 `#1e40af` 深蓝，侧边栏 `#1f2937` 深灰，页面背景 `#f5f6f8`；主题令牌在 `main.tsx`，页面里不要另写主色值。
- **禁止紫色系渐变**。配色克制、企业风，纯色优先。
- 产品名固定"智枢·智能体平台"，左上角 logo 文案不得改动。
- 卡片用 `tech-card`：圆角、细边框、轻阴影、hover 上浮。表头浅灰底由主题令牌统一。
- 状态用语义色 `Tag`，映射全站一致：

| 状态 | 颜色 |
|---|---|
| published / success / ready | green |
| draft / awaiting_review | orange |
| running / processing | blue |
| failed | red |
| cancelled / 其他 | default |

- 空状态用 `Empty`；不裸堆组件，不写魔法色值。
- 交互元素有 hover / disabled 状态；可点区域不小于 32×32。

## 7. 表格与列表

- `rowKey="id"`，`scroll={{ x: 'max-content' }}`，分页配置与第 1 节模板一致。
- 列表页统一用 `ListPage` 骨架（页头 / 统计卡 / 筛选条 / 批量条钉死，只有表格滚）+ `usePagedList(fetcher, { filters, defaultSort, selectable, emptyText })`（`src/hooks/usePagedList.ts`），把返回的 `tableProps` 展开到 `<Table>`；筛选条件放进 `filters`（用 `useQueryState` 同步到 URL，刷新不丢、可分享），变化时自动回到第 1 页；hook 用请求序号丢弃过期响应。**页面上不许再做任何前端过滤**，服务端分页下前端过滤只能筛当前页。
- 排序走服务端：列定义展开 `{ ...sortProps('latency_ms') }`，hook 把 `sort / order` 传给后端（字段须在接口白名单里）。
- 批量操作：`selectable: true` 得到行选择，`BatchActionBar` 列出动作，`useBatchAction` 执行后端 `batchXxx`，失败清单用 `BatchResultModal` 展示。
- 状态列一律 `<StatusTag domain value />`（`constants/status.ts` 是唯一字典，英文裸值不许上屏）；时间列 `<TimeCell />`；关联列 `<ResourceLink />`；Token 列 `<TokenUsage compact />`。
- 下拉选项用 `listXxx(OPTIONS_PAGE)` 取第一页最多 100 条并开 `showSearch`；统计数字优先用 `/stats/*` 接口，不再用 `page_size=1` 拼凑。
- 列宽、对齐、同一字段的表头名在各页面保持一致（ID 60、状态 110、操作列固定宽）。
- 数字或编号列按自然序排序。
- 详情页用 `DetailPage` 骨架（面包屑 / 标题 / 标签 / 关键信息 / 操作区 + 页签，页签面板是唯一滚动区，`?tab=` 深链）；详情页里的嵌入表格用普通分页，不再套 `fixed-table-wrapper`。

## 8. 表单

- 新增/编辑共用一个 `Modal + Form`，`destroyOnClose`，提交按钮在请求中加载态或禁用。
- 校验规则写在 `rules`，服务端仍会再校验一遍，前端校验只是体验。
- 下拉选项来自接口（模型、工具、知识库、智能体），不在组件里硬编码值-标签表；角色、状态这类固定枚举的中文映射集中在 `constants/status.ts`（`statusOptions(domain)` 给筛选下拉，`StatusTag` 给展示，同源）。
- JSON 参数输入先 `JSON.parse` 校验再提交，解析失败明确提示。

## 9. 组件拆分

- 单文件超过 300 行就拆：独立交互区块拆子组件，可复用状态拆 hook，纯函数与类型拆独立模块。粒度约定：页面编排 ≤ 150 行、列定义 `xxxColumns.tsx` ≤ 100、表单 / 抽屉 ≤ 150；低于 40 行的碎片不单独成文件。（`WorkflowEditor.tsx` 已于 2026-09-05 拆分。）
- 展示组件不发请求，数据由页面注入（`components/chat/*` 是范例）。
- props 明确类型；共享类型放 `components/<域>/types.ts`。

## 10. 类型

- `tsconfig` 目前 `strict: false`，存量代码大量 `any`。**新代码不许新增 `any`**：接口返回类型在 `api/<域>.ts` 里定义并导出（`AgentRow`、`RunRow`、`StatsOverview`…），页面直接引用。
- ID 按 `number` 处理，比较用 `===`；不要 `String(id)` 与数字混比。
- 后端可空字段显式处理（`c.title || '对话'`），不要 `?.` 一路穿透后渲染出 `undefined`。

## 11. 移动端

- `Grid.useBreakpoint()`，`!screens.md` 视为移动端。
- 侧边栏收进 `Drawer` + 汉堡按钮；表格横向滚动；编辑器的节点库与配置面板分别用左抽屉与底部抽屉。
- 触摸目标不小于 44×44；底部固定栏留安全区。

## 12. 验证分工

| 类型 | 谁做 |
|---|---|
| `npx tsc --noEmit`、`npm run build`、控制台无报错 | 开发者（含 AI）交付前必做 |
| 布局对不对、交互顺不顺、业务是否符合预期 | **由使用者决定**：自己看、让 AI 跑自动化、或不需要验证。每次前端改动交付时都要问，不许自作主张 |

交付说明写清：改了哪几个页面、每处重点看什么、已知未验证点。
