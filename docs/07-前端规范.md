# 智枢·智能体平台 前端规范

版本 V2.1 · 2026-09-04 · 适用于 `frontend/`

> 先读 `05-开发规范.md`，本文档只写前端特有的约定。技术栈：React 18 + TypeScript + Vite 5 + Ant Design 5 + React Router 6 + zustand + axios + @xyflow/react。

## 1. 页面骨架与滚动（最高频错误，先看）

**滚动条只能出现在中间内容区；顶部操作区与底部分页钉死；整页一起滚 = 错。**

外层容器由 `AppLayout` 提供：`Content` 已是 `flex: 1; min-height: 0; display: flex; flex-direction: column`，内容区外还包了一层 `overflow: hidden`。页面根元素只需要接上这条链：

```tsx
<div style={{ flex: 1, minHeight: 0, display: 'flex', flexDirection: 'column', gap: 16 }}>
  <div style={{ display: 'flex', justifyContent: 'space-between', flexShrink: 0 }}>
    <h2>页面标题</h2>
    <Button type="primary">操作</Button>
  </div>
  <div className="fixed-table-wrapper">
    <Table rowKey="id" loading={loading} dataSource={data} columns={columns}
      scroll={{ x: 'max-content' }}
      pagination={{ position: ['bottomRight'], showSizeChanger: true, showTotal: (t) => '共 ' + t + ' 条' }} />
  </div>
</div>
```

- 根元素 `flex: 1; minHeight: 0`；**`minHeight: 0` 必写**，否则 flex 子项不肯收缩，滚动条会跑到外层。
- 顶部区 `flexShrink: 0`。
- 列表页表格必须包在 `fixed-table-wrapper` 里，由它让表体内部滚动、分页固定底部（样式在 `styles.css`）。
- 禁止 `height: calc(100vh - ...)` 这类写死高度；禁止在页面根元素上写 `overflow: auto` 让整页滚（只有工作台这种纯卡片页例外）。
- 对话页：会话列表与消息区各自滚，输入框钉死；编辑器页：画布区 `flex: 1; minHeight: 0`，左右面板各自 `overflow: auto`。
- 弹窗与抽屉同理：头尾钉死，内容区滚。

## 2. 目录与分层

| 位置 | 放什么 | 不放什么 |
|---|---|---|
| `api/client.ts` | axios 实例与拦截器 | 业务接口函数 |
| `api/index.ts` | 全部接口的具名函数；SSE 解析器 | 组件逻辑 |
| `store/` | 跨路由的领域状态（当前用户、token） | 某个页面的临时表单值 |
| `components/` | 可复用组件；`chat/` 下是对话消息子组件与共享类型 | 发请求 |
| `pages/` | 一路由一文件，负责取数、状态与编排 | 直接 `axios / fetch` |
| `styles.css` | 全局样式与可复用类 | 页面私有样式（页面私有的用内联 style） |

## 3. 请求层

- 组件只 `import { listAgents } from '../api'`，不关心 URL、请求头、token。
- 新接口先在 `api/index.ts` 按 URL 搜一遍，命中就复用；一个接口只封装一次。
- 函数命名 `listXxx / createXxx / updateXxx / deleteXxx / <动作>Xxx`，参数只传意图相关字段。
- 拦截器已把响应解包成 `res.data`，所以 `const list = await listAgents()` 直接是数组。
- 错误提示统一写法：`message.error(e.response?.data?.detail || '操作失败')`；批量操作说明失败了哪几条。
- 对话流式走 `chatAgentStream`（fetch + ReadableStream），因为 axios 不支持浏览器端流式读取。新增 SSE 事件类型在这里加分支，同批改后端与 `04-接口设计.md`。
- **竞态**：快速切换会话或筛选时先发的请求可能后到。当前只有对话页用 `AbortController` 处理了停止；新写的带筛选列表要用请求序号或 AbortController 丢弃过期响应。
- 轮询与定时器在组件卸载时清理；文档处理状态用"上传后延迟刷新"而不是长轮询。

## 4. 三态：加载 / 空 / 错误

- 异步区域必须处理三种状态且互斥：`loading` 时不显示"暂无数据"。
- 表格用 `loading` 属性；列表用 `Empty` 或 `locale.emptyText`；空态要说明下一步能做什么（"从节点库拖入节点开始编排"）。
- 切换会话或页签时先清空旧数据再加载，避免新页签露出上一屏内容。
- 请求失败必须有可见反馈，禁止 `catch {}` 静默。现状里 `Dashboard.tsx`、`Chat.tsx` 有静默 catch，属待改项，新代码不许再增加。

## 5. 状态管理

- 全局 store 只有 `useAuth`（token、user、setAuth、logout），持久化在 localStorage。
- 页面内状态用 `useState`；父子共享用 props；跨路由共享才进 store。
- 派生数据用计算，不维护第二份副本；流式追加消息时按 `Chat.tsx` 的 `patchLast` 做不可变更新，不原地改数组。
- 服务端数据与编辑态分离：编辑弹窗用 `form.setFieldsValue(record)` 拷贝，不直接改列表里的对象。

## 6. 视觉与品牌

- 主色 `#1e40af` 深蓝，侧边栏 `#1f2937` 深灰，页面背景 `#f5f6f8`；主题令牌在 `main.tsx`，页面里不要另写主色值。
- **禁止紫色系渐变**。配色克制、企业风，纯色优先。
- 产品名固定"智枢·智能体平台"，左上角 logo 文案不得改动。
- 卡片用 `tech-card`：圆角、细边框、轻阴影、hover 上浮。表头浅灰底由主题令牌统一。
- 状态用语义色 `Tag`，映射全站一致：

| 状态 | 颜色 |
|---|---|
| published / success / ready | green |
| draft / awaiting_review | orange |
| running / processing | blue |
| failed | red |
| cancelled / 其他 | default |

- 空状态用 `Empty`；不裸堆组件，不写魔法色值。
- 交互元素有 hover / disabled 状态；可点区域不小于 32×32。

## 7. 表格与列表

- `rowKey="id"`，`scroll={{ x: 'max-content' }}`，分页配置与第 1 节模板一致。
- 现状是前端分页（后端全量返回）。**后端分页上线后**：`pagination` 改为受控（`current / pageSize / total / onChange`），筛选条件全部传给接口，页面上不再保留任何前端过滤；运行记录页的统计卡片改由接口聚合返回。
- 列宽、对齐、同一字段的表头名在各页面保持一致（ID 60、状态 110、操作列固定宽）。
- 数字或编号列按自然序排序。

## 8. 表单

- 新增/编辑共用一个 `Modal + Form`，`destroyOnClose`，提交按钮在请求中加载态或禁用。
- 校验规则写在 `rules`，服务端仍会再校验一遍，前端校验只是体验。
- 下拉选项来自接口（模型、工具、知识库、智能体），不在组件里硬编码值-标签表；角色这类固定枚举的中文映射集中在一处（现状在 `AppLayout.tsx` 的 `roleLabel`，扩展时抽到公共模块）。
- JSON 参数输入先 `JSON.parse` 校验再提交，解析失败明确提示。

## 9. 组件拆分

- 单文件超过 300 行就拆：独立交互区块拆子组件，可复用状态拆 hook，纯函数与类型拆独立模块。`WorkflowEditor.tsx` 已超限，下次改动它时先拆（节点库、配置面板、测试运行三块）。
- 展示组件不发请求，数据由页面注入（`components/chat/*` 是范例）。
- props 明确类型；共享类型放 `components/<域>/types.ts`。

## 10. 类型

- `tsconfig` 目前 `strict: false`，存量代码大量 `any`。**新代码不许新增 `any`**：接口返回类型在 `api/index.ts` 旁定义并导出，页面直接引用。
- ID 按 `number` 处理，比较用 `===`；不要 `String(id)` 与数字混比。
- 后端可空字段显式处理（`c.title || '对话'`），不要 `?.` 一路穿透后渲染出 `undefined`。

## 11. 移动端

- `Grid.useBreakpoint()`，`!screens.md` 视为移动端。
- 侧边栏收进 `Drawer` + 汉堡按钮；表格横向滚动；编辑器的节点库与配置面板分别用左抽屉与底部抽屉。
- 触摸目标不小于 44×44；底部固定栏留安全区。

## 12. 验证分工

| 类型 | 谁做 |
|---|---|
| `npx tsc --noEmit`、`npm run build`、控制台无报错 | 开发者（含 AI）交付前必做 |
| 布局对不对、交互顺不顺、业务是否符合预期 | **由使用者决定**：自己看、让 AI 跑自动化、或不需要验证。每次前端改动交付时都要问，不许自作主张 |

交付说明写清：改了哪几个页面、每处重点看什么、已知未验证点。
