## 1. 页面骨架与滚动（最高频错误，先看）

**滚动条只能出现在中间内容区；顶部操作区与底部分页钉死；整页一起滚 = 错。**

外层容器由 `AppLayout` 提供：`html / body / #root` 是 100% 高度链加 `overflow: hidden`（`styles.css`），`<main>` 与其内层都是 `flex: 1; min-height: 0; display: flex; flex-direction: column; overflow: hidden`。列表页直接用 `ListPage` 骨架接上这条链（页头 / 提示 / 统计卡 / 筛选条 / 批量条钉死，只有表格滚）：

```tsx
const list = usePagedList(listThings, { filters, selectable: true, emptyText: <EmptyState … /> })   // 服务端分页 + 排序 + 竞态保护，见第 7 节

<ListPage
  header={<PageHeader icon={<Bot />} title="页面标题" extra={<Button variant="primary" size="md" icon={<Plus />}>操作</Button>} />}
  filters={<FilterBar onReset={resetFilters} onRefresh={list.reload}>…</FilterBar>}
  batch={<BatchActionBar count={list.selectedKeys.length} onClear={list.clearSelection} actions={…} />}
>
  <DataTable
    columns={columns} rows={list.items} rowKey={(r) => r.id}
    loading={list.loading} error={list.error} onRetry={list.reload} empty={<EmptyState … />}
    page={list.page} pageSize={list.pageSize} total={list.total} onPageChange={list.load}
    sort={list.sort} onSortChange={list.setSort}
  />
</ListPage>
```

自己写骨架时（对话页、编辑器这类非列表页）根元素 `flex: 1; minHeight: 0; display: flex; flexDirection: column`，顶部区 `flexShrink: 0`，中间唯一滚动区 `flex: 1; minHeight: 0; overflow: auto`。

- 根元素 `flex: 1; minHeight: 0`；**`minHeight: 0` 必写**，否则 flex 子项不肯收缩，滚动条会跑到外层。
- 顶部区 `flexShrink: 0`。
- `ListPage` 的 `fixed-table-wrapper` 只负责 flex 链（`flex: 1; min-height: 0`）；表格自己的滚动、横向溢出、右钉操作列都由 `components/table/DataTable` 内部处理，页面不要再套第二层滚动容器。窄屏（`< sm`）下 DataTable 自动从表格切成卡片列表，用 `primary` / `hideOnMobile` / `pinRight` 控制卡片里显示哪些列。
- 禁止 `height: calc(100vh - ...)` 这类写死高度；禁止在页面根元素上写 `overflow: auto` 让整页滚（只有工作台这种纯卡片页例外）。壳层高度用 `html / body / #root` 的 100% 链加 `overflow: hidden`，不用 `100vh`：使用者浏览器里 `100vh` 与真实视口差了几十像素，滚轮一动整页位移（2026-09-06）。
- 对话页：会话列表与消息区各自滚，输入框钉死；编辑器页：画布区 `flex: 1; minHeight: 0`，左右面板各自 `overflow: auto`。
- 弹窗与抽屉同理：头尾钉死，内容区滚。

### 2.1 组件库（shadcn/ui + Tailwind v4）

- 两层：`components/shadcn/`（CLI 生成的原样组件，**不要改动里面的样式常量**）和 `components/ui/`（项目口径封装）。
- `ui/` 目前只封装了**语义固定的那几件**：`Button`（primary/secondary/ghost/danger × sm/md）、`Modal`、`Drawer`、`Badge`、`InlineConfirm`、`confirm`。**凡是 `ui/` 里有的，一律从 `ui/` 引，不要绕过它直接用 shadcn 的对应件**（那样会丢语义和尺寸）。
- 其余基础件（`input`、`textarea`、`label`、`select`、`tooltip`、`popover`、`dropdown-menu`、`tabs`、`switch`、`checkbox`、`sheet`、`dialog`、`alert`、`skeleton`、`calendar`）直接从 `components/shadcn/` 引，这是当前既定口径，不要为了"多层"再包一层空壳。
- 需要改 shadcn 组件的默认行为时（加 `forwardRef`、改默认尺寸），改生成件本身并在文件头注释写明为什么；否则一律靠 `className` 在调用处覆盖。
- **不要手搓**：能组合 shadcn 的（弹窗、抽屉、下拉、提示、表格、日历、骨架）一律用组件，别自己写 div + 事件。手搓之前先在 `components/ui/` 和 `components/shadcn/` 里搜一遍。
- `cn()` 从 **`cn` 这个 npm 包**引（`import { cn } from 'cn'`），不是 `clsx` + `tailwind-merge` 手拼。
- Tailwind v4 是 **CSS-first**，没有 `tailwind.config.js`：主题变量写在 `styles/theme.css` 的 `@theme inline` 里，新 token 加在那里才会生成对应原子类。
- 样式优先级：Tailwind 原子类 > `styles.css` 里的类 > 内联 style。**内联 style 会盖掉原子类**，组件库内联写死的属性（如 `liquid-glass-react` 的 `box-shadow`、`overflow`）只能靠 `!important` 覆写。
- 重新跑 `npx shadcn@latest add <组件>` 会**覆盖** `shadcn/button.tsx`、`shadcn/badge.tsx` 里手工加的 `forwardRef`；重跑后要检查这两个文件的 `ref` 还在不在。
- 图标一律用 `lucide-react`（`<Plus className="size-3.5" />`），不用 emoji、不引第二套图标库。
- 全局提示用 `sonner` 的 `toast.success / toast.error(errorText(e, '…'))`；不用 `window.alert`。

## 3. 请求层

- 组件只 `import { listAgents } from '../api'`，不关心 URL、请求头、token。
- 新接口先在 `src/api/` 目录按 URL 搜一遍，命中就复用；一个接口只封装一次，放进对应领域文件。
- 函数命名 `listXxx / createXxx / updateXxx / deleteXxx / <动作>Xxx`，参数只传意图相关字段。
- 拦截器已把响应解包成 `res.data`；列表函数返回 `Page<T>`（`{items, total, page, page_size}`），`api/core.ts` 的 `get / post / put / del<T>()` 已收窄类型，页面不要再 `as any`。
- 错误提示统一 `toast.error(errorText(e, '操作失败'))`（`sonner` + `utils/errors.ts`）：字符串 detail 直接用，422 数组取首条 msg；成功提示 `toast.success(...)`；批量操作用 `BatchResultModal` 说明失败了哪几条。
  5xx 的追踪 ID 已由 `client.ts` 拦截器拼进 `detail`（形如"服务器内部错误…（trace: 1de7aa…）"），页面不用自己拼。
- 依赖状态用 `useSystemStatus()`（共享 store，多个订阅者共用一个定时器，页面不可见时暂停）：`degraded` 非空由 `DegradedBanner` 在顶栏下统一提示；页面只在需要局部信息时读 `status.embedding / model_breakers / scheduler`，不要各页面自己判断、也不要再直接调 `getSystemStatus()`。
- 对话流式走 `api/chat.ts` 的 `streamSse`（fetch + ReadableStream），因为 axios 不支持浏览器端流式读取；401、422、5xx 的处理与 `client.ts` 拦截器同一口径（401 共用 `clearLoginAndRedirect`）。新增 SSE 事件类型在这里加分支，同批改后端与 `04-接口设计.md`。新的对话入口（装配页调试、分享访客）写一个 `streamSse` 的薄封装，不另写解析；令牌来源、401 处理、读响应头由最后一个参数 `SseAuth` 注入，默认是平台登录态。
- **分享访客是唯一不走 axios 实例的非流式请求**（2026-10-05 起，`15` 3.6）：`api/share.ts` 的访客函数用 fetch——axios 实例会注入平台 token、401 时清登录态跳登录，访客页两样都不能要。访客令牌按链接存 localStorage 的 `share_token:<code>`，响应头 `X-Share-Token` 有值时替换；非 2xx 抛 `RequestError`（带 `status`），页面按 404 / 403 / 401 分支到状态页或重新进入。同文件的分享管理接口（`/agents/{id}/share`）仍走 axios 实例。其余接口不要仿照这里另起 fetch。
- 对话界面一律用 `components/chat/ChatPanel`（头部插槽 + 消息流 + 输入条）+ `useChatStream`：发送函数由页面注入（`transport`），能看到哪些过程信息由 `capabilities` 决定（运行记录链接、工具入参与结果、引用、Token、重新生成），组件默认"最少暴露"。登录对话页按角色给（admin / developer 全开，调用者不看运行记录链接与工具入参结果，`15` D-19），调试面板全开，分享访客页只放开"显示引用"（按链接配置），其余保持最少暴露。
- **竞态**：快速切换会话或筛选时先发的请求可能后到。列表页交给 `usePagedList` 的请求序号处理；详情页、抽屉、统计卡用 `useAsyncData`（同样带请求序号）；对话页用 `AbortController`；不能裸 `await` 后直接 set。
- 请求超时默认 30 秒（`client.ts`），文档上传这类大请求单独传 `timeout: 0` 并用 `onUploadProgress` 报进度，不要改全局超时。
- 轮询与定时器在组件卸载时清理。文档处理状态：**只在有处理中（uploading / parsing / chunking）的文档时每 3 秒轮询，没有处理中的即停，页面不可见时暂停**（2026-09-06 修订，取代"上传后延迟刷新"）；运行详情在非终态时同样有界轮询。
- 关联跳转一律用 `<ResourceLink type id name />`（`constants/resources.tsx` 是唯一映射）：详情页型资源跳 `/xxx/:id`，抽屉型资源跳列表页 `?open=:id`（列表页用 `useOpenParam` 响应）。抽屉里出现的关联也跳页面，**不在抽屉上再叠抽屉**；抽屉里要编辑就用弹窗（模板页 2026-09-06 改法）。
- 计数列跳到"按它筛选的列表"（如模型的智能体数跳 `/agents?model_id=`）时，目标列表必须把该参数放进 `useQueryState` 的默认值里真正下推到服务端，并在筛选条显示为可关闭的标签（`AgentFilters` / `RunFilters` 的写法）；只放在 URL 里不生效的链接等于骗人。
- 开发与 preview 的反代键是正则 `^/api/`，不能写成前缀 `/api`：前端路由 `/api-keys` 会被吃掉（见 `08` 2.2）。新增以 `api` 开头的路由前先想到这条。

## 4. 三态：加载 / 空 / 错误

- 异步区域必须处理三种状态且互斥：`loading` 时不显示"暂无数据"。
- 表格用 `usePagedList` 的 `emptyText` 选项（加载中留白、失败显示错误、否则显示空态）；卡片 / 详情用 `useAsyncData` 的三态配 `ErrorState`（带重试）与 `EmptyState`（带下一步动作）；空态要说明下一步能做什么（"从节点库拖入节点开始编排"）。
- 切换会话或页签时先清空旧数据再加载，避免新页签露出上一屏内容。
- 请求失败必须有可见反馈，禁止 `catch {}` 静默。

## 5. 状态管理

- 全局 store 只有四个：`useAuth`（token、user、setAuth、logout，持久化在 localStorage）、`useSystemStatusStore`（系统状态共享轮询，只通过 `useSystemStatus()` 订阅）、`useUnsaved`（编辑器未保存标记，菜单与 beforeunload 据此拦截）、`useTheme`（主题 `theme` 与液态玻璃开关 `glass`，持久化在 localStorage，首帧由 `main.tsx` 直接写 `<html data-theme / data-glass>`）。
- 页面内状态用 `useState`；父子共享用 props；跨路由共享才进 store。
- 派生数据用计算，不维护第二份副本；流式追加消息时按 `components/chat/useChatStream.ts` 的写法做不可变更新，不原地改数组。
- 服务端数据与编辑态分离：编辑弹窗打开时用 `react-hook-form` 的 `reset(record)` 灌一次值，不直接改列表里的对象。

## 6. 视觉与品牌

- 颜色一律用语义令牌，**页面里不许写死色值**：`--bg / --bg-elev / --bg-soft / --fg / --fg-muted / --border / --accent / --accent-fg / --radius / --shadow`，语义色另有 `--danger / --success / --warning / --info`（各带 `-soft` 变体）。令牌定义在 `src/styles/theme.css` 的 `:root` 与 `[data-theme="…"]` 块里，共 8 套配色（indigo / celadon / navy / sand / fuchsia / graphite / deep / midnight），切换只改 `<html data-theme>`，不改组件。新增一套配色 = 复制一个块改 20 个变量，不要动组件。
- **禁止紫色系渐变**。配色克制、企业风，纯色优先。
- 产品名固定"智枢·智能体平台"，左上角 logo 文案不得改动。
- 卡片统一写 `rounded-xl border border-border bg-card`（`bg-card` 由 `@theme inline` 映射到 `--bg-elev`），内边距 `p-4` 起。`.tech-card` 是 antd 时代留下的死样式（无组件引用、色值写死 `#e5e7eb`），**不要再用**。表头底色由主题令牌统一。
- 状态一律 `<StatusTag domain value />`，文案与颜色只在 `constants/status.ts` 定义一次，语义色约定：

| 状态 | 颜色 |
|---|---|
| published / success / ready | green |
| draft / awaiting_review | orange |
| running / processing | blue |
| failed | red |
| cancelled / 其他 | default |

- 空状态用 `components/common/EmptyState`（带 `description` 与可选的下一步 `action`）；不裸堆组件，不写魔法色值。
- 交互元素有 hover / disabled 状态；可点区域不小于 32×32。

## 7. 表格与列表

- `rowKey="id"`，`scroll={{ x: 'max-content' }}`，分页配置与第 1 节模板一致。
- 列表页统一用 `ListPage` 骨架（页头 / 统计卡 / 筛选条 / 批量条钉死，只有表格滚）+ `usePagedList(fetcher, { filters, defaultSort, selectable, emptyText })`（`src/hooks/usePagedList.ts`）。hook 返回 `{ items, total, page, pageSize, loading, error, sort, setSort, selectedKeys, setSelectedKeys, clearSelection, load, reload }`，**逐个透传给 `DataTable`**（没有 `tableProps` 这种整体对象）。筛选条件放进 `filters`（用 `useQueryState` 同步到 URL，刷新不丢、可分享），变化时自动回到第 1 页；hook 用请求序号丢弃过期响应。**页面上不许再做任何前端过滤**，服务端分页下前端过滤只能筛当前页。
- 排序走服务端：列定义里给该列加 `sortable: true`（`key` 即服务端排序字段），`DataTable` 点表头触发 `onSortChange`，`usePagedList` 的 `sort` 变化后把 `sort / order` 传给后端（字段须在接口白名单里）。
- 批量操作：`selectable: true` 得到行选择，`BatchActionBar` 列出动作，`useBatchAction` 执行后端 `batchXxx`，失败清单用 `BatchResultModal` 展示。
- 状态列一律 `<StatusTag domain value />`（`constants/status.ts` 是唯一字典，英文裸值不许上屏）；时间列 `<TimeCell />`；关联列 `<ResourceLink />`；Token 列 `<TokenUsage compact />`。
- 下拉选项用 `listXxx(OPTIONS_PAGE)` 取第一页最多 100 条，配 `components/shadcn/select`（选项多时用 `SearchInput` 过滤后喂给它）；统计数字优先用 `/stats/*` 接口，不再用 `page_size=1` 拼凑。
- 列宽、对齐、同一字段的表头名在各页面保持一致（ID 60、状态 110、操作列固定宽）。
- 数字或编号列按自然序排序。
- 详情页用 `DetailPage` 骨架（面包屑 / 标题 / 标签 / 关键信息 / 操作区 + 页签，页签面板是唯一滚动区，`?tab=` 深链）；详情页里的嵌入表格用普通分页（`usePagedList` 传 `auto: false`，页签激活时再 `load`），不再套 `fixed-table-wrapper`。

## 8. 表单

- 简单对象的新增 / 编辑共用一个 `ui/Modal` + `react-hook-form` 表单（拆成 `components/<域>/XxxForm.tsx`）。`Modal` 只在 `open` 为真时挂载，关闭即卸载，不需要 `destroyOnClose`；提交中把按钮 `disabled` 并把文案改成"保存中…"（`Button` 没有 `loading` 属性，别去找）。
- 复杂对象（工作流、智能体：字段多、要边改边试）用二级编辑页 `/xxx/new`、`/xxx/:id/edit`，不用弹窗（2026-09-29 起，`15` D-01；此前智能体是 680px 弹窗，9 个字段纵向堆叠，也没处调试）。骨架：顶栏钉死（返回、名称与状态、保存、发布、更多），主体各栏各自滚动、整页不滚；整页一个 Form，页面持有请求，分区卡片只接收 props（`components/agents/editor/` 是范例）。
- 编辑页必须有未保存拦截：保存请求体与上次保存时不同即置 `useUnsaved` 的 dirty，卸载时清掉；菜单与页内"返回"都走 `useGuardedNavigate`（先确认再跳）；刷新 / 关标签页由 `AppLayout` 的 `beforeunload` 拦。浏览器后退键拦不住（BrowserRouter 下没有 `useBlocker`），在顶栏的"未保存"标签提示里写明。
- 校验规则写在 `rules`，服务端仍会再校验一遍，前端校验只是体验。
- 下拉选项来自接口（模型、工具、知识库、智能体），不在组件里硬编码值-标签表；角色、状态这类固定枚举的中文映射集中在 `constants/status.ts`（`statusOptions(domain)` 给筛选下拉，`StatusTag` 给展示，同源）。
- JSON 参数输入先 `JSON.parse` 校验再提交，解析失败明确提示。

## 9. 组件拆分

- 单文件超过 300 行就拆：独立交互区块拆子组件，可复用状态拆 hook，纯函数与类型拆独立模块。粒度约定：页面编排 ≤ 150 行、列定义 `xxxColumns.tsx` ≤ 100、表单 / 抽屉 ≤ 150；低于 40 行的碎片不单独成文件。（`WorkflowEditor.tsx` 已于 2026-09-05 拆分。）
- 展示组件不发请求，数据由页面注入（`components/chat/*` 是范例：会话删除、发送都由页面注入回调，目录下只有类型从 `api` 引入）。
- props 明确类型；共享类型放 `components/<域>/types.ts`。

## 10. 类型

- `tsconfig` 目前 `strict: false`，存量代码大量 `any`。**新代码不许新增 `any`**：接口返回类型在 `api/<域>.ts` 里定义并导出（`AgentRow`、`RunRow`、`StatsOverview`…），页面直接引用。
- ID 按 `number` 处理，比较用 `===`；不要 `String(id)` 与数字混比。
- 后端可空字段显式处理（`c.title || '对话'`），不要 `?.` 一路穿透后渲染出 `undefined`。

## 11. 移动端

- 断点用 Tailwind 的 `sm:` / `max-sm:` 变体；需要 JS 判断时用 `matchMedia`（范例 `SharePage` 的 `useIsMobile`），不要再引 UI 库的 `useBreakpoint`。
- 侧边栏收进 `Drawer` + 汉堡按钮；表格横向滚动；编辑器的节点库与配置面板分别用左抽屉与底部抽屉。
- 触摸目标不小于 44×44；底部固定栏留安全区。
- 已有的落地方式（2026-10-05 起，`15` CH-14）：`index.html` 的 viewport 带 `viewport-fit=cover`（内容铺到刘海与手势条下）与 `interactive-widget=resizes-content`（Android 弹键盘时缩布局视口）；`#root` 左右让出 `env(safe-area-inset-left/right)`，钉底的栏自己叠加 `env(safe-area-inset-bottom)`（范例 `ChatInput`）；触屏放大点按区域写在 `@media (pointer: coarse)` 里，不影响鼠标设备；只靠悬停才能看到的信息（引用角标）要同时支持点按（`trigger={['hover', 'click']}`）；整页钉底输入的页面用 `useVisualViewportHeight` 取可视视口高度做整页高度（iOS 弹键盘不缩布局视口）。
- 回车发送的输入框必须自己判断输入法组合态（`e.nativeEvent.isComposing || e.keyCode === 229` 时不发送）：原生 textarea 的 `keydown` 不判断，拼音选词的回车会把半截拼音发出去。
